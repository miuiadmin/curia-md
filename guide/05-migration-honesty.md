# 05 迁移的诚实面

一句话：本章回答九条问题里的第 5 条（迁移/采用一棵文档树时的静默失败清单与找坑方法；清单按实测给，完整性边界见「诚实条款」），并给出「无损迁移」今天能承诺的四条可判定事实、四条明示的不可判定面；底线只有一条——已修的是一批实测形态，不是「不会再有」。

本章源料（参考实现仓内相对路径，正文引用用简称加小节标题）：定义调研＝`.agents/research/2026-10-20-curia-lossless-migration-definition.md`；稳定性调研＝`.agents/research/2026-10-20-curia-migration-stability.md`；修复笔记＝`.agents/notes/implemented/bug-fix/2026-10-20-curia-lossless-migration-fixes.md`；裁定笔记＝`.agents/notes/implemented/process/2026-10-20-curia-migration-stability-decisions.md`；包 README＝`create-curia/README.md`；规范＝`.agents/README.md`；仓规则＝`AGENTS.md`。

## 「无损」的定义：四条可判定事实

「迁移」与「安装」的差别决定了定义的范围：用户说的是「迁移」，所以宿主既有的文档、根规则、桥路径在迁移后处于什么状态，是定义绕不开的一半（定义调研「问题」）。

定义由两版独立对撞得出：一版从规范承诺面推、36 条，一版从失败面推、34 条，共 70 条；条目归六块——传输面、入口接通、机械子集通过、宿主侧零丢失、纳管与登记、身份与漂移（定义调研「两版定义」）。

判定标准是「写得出核对动作才算数」；写完不自己核，每版各派一名复验员专造反例，反例优先实测，并明令优先攻击标了「已达标」的条目——那才是定义敢承诺的部分（定义调研「方法与来源」）。

攻击结果：六条反例全部实测、全部打在标了「已达标」的条目上；共同根因是判据用了代理指标——退出码、`readlink` 字面、单短语搜索、exit-0 全绿。代理指标本身没有错，错在把「探针通过」当成了「性质成立」（定义调研「结论」）。

据此收敛，「无损」今天最多能承诺四条，各带可跑判据（定义调研「结论」）：

- 载荷字节落地：空宿主上 `init` 新建 21 件、退出码 0；直拷形态按 `cp -an` 后件数可比对（包 README「跑完怎么确认装对了」「备选：直接拷贝」）。
- 机制接线：三条桥按「真解析得到、且落在目标仓内」判定接上，`init` 报「未接上 0」才算接上（修复笔记「Decision」一；包 README「跑完怎么确认装对了」）。
- 机械子集通过：`node .agents/tools/check-docs.mjs --strict` 退出码 0（包 README「跑完怎么确认装对了」）。
- 既有内容零静默丢失：`init` 不覆盖既有文件、保留项逐条列出；直拷路径的破坏面有明文警告（包 README「采用到已有仓库」）。

稳定性调研另有一句更早的表述：「无损」的可核对性止于接线与身份——载荷在位、桥接上、制品可命名（稳定性调研「未决与后续」）。身份一条见下节。

## 今天达标几项

诚实的回答分两层。按条目计数：两版初判达标 17 与 11 条（共 70 条），反例攻击后按实测口径下调——下调后的最终计数报告未给出（见文末「未核实项」）。按承诺面说：四条各有可跑判据，但证据强度不同，只有传输面经得起反例（定义调研「两版定义」「结论」）。

传输面站得住：字节落地、空宿主机制、退出码四态语义、重跑幂等——这几项经得起反例，且多数已由制品与验收固化（定义调研「结论」）。

入口接通与机械子集通过两块，可核性低于其结论：定义在这两块敢说 met，靠的是可靠但不充分的判据（定义调研「结论」）；六条反例全部打在标了「已达标」的条目上，集中在入口接通与机械子集通过两块，宿主侧零丢失也中了一条（定义调研「反例」）。

两块里被实测打穿的代理判据已经换成性质判据，不新增判据面（修复笔记「Alternatives considered」）。桥判据从「`readlink` 字符串相等加 `symlinkSync` 没抛错」改成「真解析得到、且落在目标仓内」——父级解析到仓外不建桥、具名报「父级目录……解析到目标仓之外」、仓外零写入；悬空链接判未接上；建完复查一次（修复笔记「Decision」一）。

落点判据：复制步与桥步共用「真解析后须在目标仓内」，要点是「上溯到最近的存在祖先再真解析」——只看路径自身会漏掉嵌套新目录；落在仓外一律拦下、逐件具名、退出码 1，三种形态实测仓外均 0 项写入（修复笔记「Decision」一之二）。

检查器消掉两处假绿：结构组无判定对象（空 `.agents/` 不再与完整树同形，注记走 stderr、汇总行自带标注，退出码仍按告警数走）；面外类型化文档（组 2 增判带类型头块的文档住在 `.agents/` 之外）（修复笔记「Decision」三；规范「配套脚本规格」）。

两块的现状收成一句：桥的「接上」现在是真的，检查器的两处假绿消掉了；但这些都是对已实测形态的修复，不是对两块整体的重新认证（修复笔记「Consequences」）。

四条里有一条的诚实边界要单独说：「既有内容零静默丢失」的直拷一半是文档补充不是机制——`cp` 的行为改不了，只能写进警告；`init` 的不覆盖才是可核的（保留清单逐条列出）（修复笔记「Consequences」）。

代价也要记：`.claude` 指向仓外的宿主上，`init` 从退出码 0 变 3——这是要的，那些宿主上桥本来就是死的（修复笔记「Consequences」）。

## 制品身份：让「无损」有参照物

没有版本化制品之前，「无损」是相对什么而言的无法回答：`0.3.0` 曾跨三份不同字节（2.2 落地后载荷又改过两次）（稳定性调研「合成结论」；包 README「版本纪律」）。

版本纪律：包内任何文件的改动（载荷任一文件、生成器、README）必须同批跳 patch 号，使「create-curia@版本」唯一对应一份字节；判据是制品不是载荷；自 `0.3.1` 起生效；发布记 tarball 的 sha512，首个制品 tag 加 tarball 即第一份可核对参照（包 README「版本纪律」；裁定笔记「Decision」四）。

## 四条明示的不可判定面

四条：内容正确性、规则并入质量、纳管质量、迁移后长期漂移——今天既无机器判据，也无可执行的人工核对清单（定义调研「结论」）。各自的现状：内容正确性归规范「适用边界」（事实真假、结论质量、时效不查）；规则并入质量只有一条存在性核对——在宿主 `AGENTS.md` 里搜「一事实一归属」，搜不到就是没装上，但搜到只证明装上了、不证明并得好（包 README「采用到已有仓库」）；纳管质量归规范「存量树只读纳管」的六条纪律；长期漂移归 fork-and-own 结构——生成后目标仓与本包脱钩，没有 upgrade 通道（包 README「红线」）。

为什么没给这四条造机制，有三条理由。其一，规范「适用边界」已把其中多数划归采用方或评审——钩子、CI、编辑器集成、评审流程、权限模型归采用方，存量迁移与批量修复不承诺（规范「适用边界」「存量树只读纳管」）。其二，造机制需要真实事故信号，本轮没有（修复笔记「Alternatives considered」）。其三，正面撞 Owner 的口径「不要加一堆规则校验、脚本校验、门禁之类的东西，真没必要啊」——上一轮已把同族的「载荷清单自证」方案判过（修复笔记「Alternatives considered」；稳定性调研「三条候选路线与裁决」）。

有一条反向纠正值得记住：定义里曾有一版把「永不删除」与「superseded 是终态、不得迁出」列为不可判定，被打掉——`git log` 今天就能判；那是把判定面窄化成检查器脚本的偷懒免责。真缺机器面的只有「归档冻结」与无 git 宿主（定义调研「反例」）。

## 迁移的失败形态（与第三章的分工）

第三章讲「制度自身试过什么不行」；本章讲「把这套制度搬到别的仓时会怎么坏」。先给一个前置结论：包化对无损既不必要也不充分——空宿主上不做任何包化即无损；包化自己新增一条静默失败（形态三）（稳定性调研「实测证据」一、二）。

**两章清单的口径差（别当同一份读）**：第三章 §二 按「判据只看形态不看性质」「代理指标被穿透」这类**根因**归类，收的是全部成文记录；本章按**迁移这一侧的发生面**归类。本章末三条（形态十五至十七）未进第三章——它们是复核期新发现、随修复批同批处理，第三章成文时尚未出现。两章互补，都不是完整清单。

本章说的静默失败＝报「完成」或全绿、退出码 0，而机制实际没接上或漏检；裁定笔记管它叫假绿：门禁看着在跑、报告看着通过，实际漏检或空转（裁定笔记「Alternatives considered」）。

以下形态是历史记录：由 2026-10-20 两轮实测挖出，逐条注明现行口径——有的已修成显式失败（退出码 1 或 3、具名报告），有的只是把边界写进文档（如直拷破坏面），有的仍是结构性事实（如 fork-and-own 无 upgrade 通道）。

落点与传输面：

- 形态一：宿主把 `.agents/` 或 `docs/` 预先做成指向仓外的符号链接——载荷整份落到仓外、git 完全看不见，而修复前 `init` 报「完成」、退出码 0、桥 3 条全接上。现行口径：退出码 1、逐件具名「落点……解析到目标仓之外」、仓外零写入（修复笔记「Decision」一之二；包 README「采用到已有仓库」）。
- 形态二：宿主根上 `.claude` 或 `.codex` 本身是指向仓外的符号链接（dotfiles 共享配置的常见形态）——桥被建到仓外、`readlink` 字符串逐字正确、退出码 0、重跑报「已就位 3」、自检全绿，而桥是死的且不在仓里；这条由两名复验员各自独立测出。现行口径：退出码 3、具名报父级解析到仓外、仓外零写入（修复笔记「Problem」「Decision」一；包 README「采用到已有仓库」）。
- 形态三：`npm pack` 静默丢弃载荷里的 3 条桥符号链接（源 3 条到 tarball 内 0 条，零 warning）——从 tarball 直拷得到零桥工作区。现行口径：tarball 一律走 `init`；直拷只对源码树形态成立（稳定性调研「实测证据」二；包 README「分发边界」）。
- 形态四：直拷的三种静默面——`cp -R template/*` 漏掉三个点目录且退出码 0；`cp -an` 静默跳过同名文件、退出码不可靠；`cp -R`（不带 `-n`）覆盖未提交与未跟踪内容，那些字节在 git 历史里找不回。现行口径：一律 `cp -an`、拷前 `git status`、拷后数桥（包 README「备选：直接拷贝」；定义调研「反例」）。
- 形态五：包文档曾宣传一条不可用的用法（`npm create curia`——本包不发布，该命令本来也不可用）；同批记下：包名在公共分发源无人占用，一旦被抢注，这条命令会在配置如默认的机器上静默拉取并执行第三方代码。现行口径：不再宣传这条用法（稳定性调研「实测证据」六；包 README「分发边界」）。

桥与占用面：

- 形态六：宿主已有 `CLAUDE.md` 真文件或 `.claude/skills` 目录（或指向别处的链接）——修复前 `init` 打印「完成」、退出码 0，而桥 0/3、载荷 8 条通用规则全树 grep 零命中、检查器全绿（默认面是 `.agents/` 与 `docs/`，根 `AGENTS.md` 不在面内）。现行口径：退出码 3、逐条具名；退出码 3 只覆盖桥这一硬失败，「载荷根 `AGENTS.md` 被宿主保留」不进 3（稳定性调研「实测证据」三；裁定笔记「Decision」二）。
- 形态七：汇总行的「桥 N 条」曾是本次新建数——健康重跑与彻底失败同样打印 0，不可区分。现为三分计数：新建、已就位、未接上（稳定性调研「实测证据」三；裁定笔记「Decision」二）。
- 形态八：路径被占用时打印的「修复命令」曾是假成功——`mv` 加 `ln -s` 在父级是符号链接时能成功执行，成功地把桥建死、把仓外内容顶走，而所有可核判据都显示成功。现行口径：`init` 不自动修父级（只报不修）；不要自己写裸 `ln -s`——路径已是目录时它会在目录里建出同名子链接、退出码 0（定义调研「反例」；修复笔记「Alternatives considered」；包 README「采用到已有仓库」）。
- 形态九：冲突清单曾截断——超过 8 件只列 8 个名加「等」，而承诺是「不是静默」（实测 10 件冲突有 2 件不具名）。现为一行一件全列（修复笔记「Decision」二）。

扫描与假绿面：

- 形态十：空 `.agents/`（一个空目录）曾与完整树同形全绿——判据写的是「面内有没有 `.agents` 目录」，不是「有没有结构可判」。现行口径：stderr 注记加汇总行「结构组无判定对象」标注，退出码仍按告警数走（定义调研「反例」；修复笔记「Decision」三；规范「配套脚本规格」）。
- 形态十一：宿主文档用 `.mdx`/`.markdown` 时 0 篇进扫描面，「全绿」是空承诺；「空集不冒充通过」会被载荷自带的 12 篇垫成非空后失效。现行口径：规范写明扫描面只收 `.md`——只写清边界，不扩面（定义调研「反例」；修复笔记「Decision」四）。
- 形态十二：`docs/` 曾是类型-家盲区——带类型头块的文档住进 `docs/` 全程静默，而规范明写 `docs/` 不装计划与提案。现行口径：组 2 增判；扫描面内无结构锚时不判，避免误伤外部路径巡检（定义调研「反例」；修复笔记「Decision」三）。
- 形态十三：根锚点曾自脚本位置上溯——脚本放到用户主目录下执行会静默锚到那里已存在的全局 `.agents` 目录，扫 242 篇、退出码 0、零注记；而规范写着「脚本位置不限（可搬出 `.agents/tools/`）」，这句只在同树内搬动时成立。现行口径：根由调用目录决定，默认调用下根锚点缺失必红（退出码 2）、不做上溯，每次调用先打印被检树（稳定性调研「实测证据」五；裁定笔记「Decision」一；包 README「验收（维护方）」）。
- 形态十四：报告模式有发现也退出码 0——规范已明文记载、属有意设计，但它是「把检查器直接写进 CI 而漏 `--strict` 就全绿空转」的陷阱（稳定性调研「实测证据」五；规范「配套脚本规格」）。

制度级混血与代际漂移面：

- 形态十五：文件级搬运制造制度级混血——某采用仓只把 2.2 版检查器单件补进 `.agents/tools/`，检查器立刻在自家 `.agents` 报出 15 条：该仓自有的类型与目录被判「不在 9 类内」「不是家」（稳定性调研「实测证据」四）。
- 形态十六：代际漂移——同一采用仓接入后 7 天内载荷连换两代，宿主未跟且无法跟：fork-and-own 没有 upgrade 通道（稳定性调研「实测证据」四）。
- 形态十七：装机「完成」不等于机制接上——另一采用仓载荷逐字节一致（19/19）、闸门面 626 篇 0 条、退出码 0，但达到该状态用了一天人工排障；接入时 `.claude/skills` 被占，桥以「真目录加 32 条逐技能链接加 2 个 zip」形态起步，新增技能须手工建链且无机器拦截；根 `CLAUDE.md` 至今仍是宿主真文件，3 条桥只装了 2 条（稳定性调研「实测证据」四）。

## 怎么系统地找这类坑

方法来自两轮实践；两轮各用一支多代理 workflow（九代理与八代理），三阶段：取事实、独立开方或独立定义、对抗验证（稳定性调研「方法与来源」；定义调研「方法与来源」）。可复用的做法：

1. 定义先行、反例后打：先把「无损」写成可判定条目（写不出核对动作的不算），再派复验员专造反例，优先攻击标了「已达标」的条目（定义调研「方法与来源」）。
2. 造宿主形状实跑，不靠推理：空宿主、全占用宿主、部分占用宿主、父级符号链接、空 `.agents/`、脏工作树、重复迁移、tarball 形态、非 main 分支，都在临时目录里实跑（稳定性调研「方法与来源」；定义调研「方法与来源」）。
3. 真仓只读实测：五个宿主仓的桥形态、载荷件逐字节比对与版本代际判定（稳定性调研「方法与来源」）。
4. 从承诺面逐条挖：把规范全文的「明文承诺」与「明示不承诺」逐条挖出，逐项判定今天有没有判据（定义调研「方法与来源」）。
5. 找共同根因，不逐个打补丁：六条反例的共同根因是代理指标；修法是「不新增判据面，只把已有判据的代理指标换成性质指标」（修复笔记「Alternatives considered」）。
