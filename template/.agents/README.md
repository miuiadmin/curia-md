# Curia 2.5 文档管理规范

一句话说明：Curia 2.5 是可移植的文档管理方案——两根、四句口诀定家、10 类文档、3 行头块、1 支轻量配套脚本，丢到任何项目都能用。

本规范正文以 `.agents/README.md` 为载荷载体（目录入口与总规格）：采用方进入 `.agents/` 第一眼看到的就是它。整段可拷进任何仓库、不必删改；它讲的是「怎么管理文档」，不是软件系统，配套检查脚本是轻量自检工具，不是门禁体系。

> 快速上手（第一次写文档）：1）选类型——查「10 类文档」表；2）选家——按「四句口诀」；3）抄对应骨架、落头块——见「规范格式（骨架）」；4）改完跑 `node .agents/tools/check-docs.mjs` 自检（可选）。

## 背景

Curia 2.5 回答一个问题：一个项目怎么管理自己的文档，才能让写文档的人与 Agent 不用先学一套平台。规范本体是纯 Markdown 约定与纯文本纪律——怎么写、放哪、怎么检索、怎么退役——配套只有一支轻量检查脚本。

它由单仓 12 天拦截台账的实测结论收敛而来（口径见「适用边界」）：保留持续拦截真实错误的机械子集（头块与生命周期、家与命名、链接），不做从未触发的治理面（断言、Run、受保护交付、注册表、台账、自证矩阵）。被采用项目的根 `AGENTS.md` 引用本规范，约束其文档树。

2.5 新增的两项只读诊断（`--health`、`--suggest-standards`）来自一次 14 个采用方的只读调研，把安装形态的完整性与存量标准的候选线索变成可读清单——不新增门禁，也不自动修复。

## 范围

**是什么。** 一份关于「怎么管理文档」的指导方案：文档放哪（家）、是什么（类型）、长什么样（头块与骨架）、怎么引用与检索、过时了怎么退役。它约束文档树的写法与结构；它不是软件系统——没有运行时、服务、数据库、网络调用、权限模型、审批流、CI 或钩子，也不替你决定工作流程。

**不是什么。** 不是治理平台、不是流程引擎、不是门禁体系：配套检查脚本是轻量自检工具，只证明机械子集（见「配套脚本规格」与「适用边界」），不核验事实、不发布、不审批。

- 覆盖：两根布局与家归属；10 类文档与笔记的格式；`docs/` 标准的类型、状态、版本与取代；写作、链接与检索规则；取代链与现行版本的解析；1 支检查脚本的规格；存量树只读纳管；归档四步。
- 不覆盖：迁移工具与批量修复（见「存量树只读纳管」）；钩子与 CI 接线（归采用方，规范只给 `--strict` 与退出码）；时效复核与事实核验（明文不做，见「写作规则」）；「取代是否成立」的实质判断（机器只保证链的形态与终点可解析，见「适用边界」）；多读者权限与对外发布面（另立系统，不属文档树）。

**解耦判据（可核验）。**

1. 分发文本可整段拷进任何仓库：不含指向宿主仓的爬升链接（`rg -n '\]\(\.\.' <分发文本>` 零命中），放进载荷树跑 `check-docs --strict`，链接零报。
2. 脚本零依赖：只用 Node 内置模块，不联网。
3. 可移植运行：把 `.agents/`（规范、脚本、文档）拷进无 git、无 `node_modules` 的目录，检查脚本照常运行并给出判定。
4. 无隐性前置：不装钩子、不接 CI、不用 git 也能完整使用。

## 契约

### 模型本体

**两根，封顶两根。**

| 根 | 装什么 | 不装什么 |
|---|---|---|
| `.agents/` | 过程与过程产物：计划、调研、决策笔记、技能、归档。 | 外部事实登记、跨模块/对外的现行标准与契约、面向最终读者的发布内容。 |
| `docs/` | 结果性知识与契约：仓外系统的登记与定义（资源 ID、字段映射、端点、协议）；自由知识无头块、当前版即唯一真相；现行标准用 `Type: standard`，带轻量状态机与 `Version`。 | 计划与提案、决策因果、原始事实快照、过程性技能与操作手册。 |

受管面封顶这两根，不再设第三根；项目可以只启用其中一根。

**四句口诀（放哪的最后裁决）。**

1. 没做的 → `plans/`（proposal / spec / plan）
2. 做完的 → `research/`（survey / evidence / postmortem / reference）
3. 为什么 → `notes/`（决策因果，永远不进 research）
4. 过时的 → 状态翻转优先，冷历史进 `archive/` 封存；**永不删除**

补：可复用的干法 → `skills/`（skill / runbook）；外部事实与现行标准 → 根 `docs/`——自由知识无头块，现行标准写 `Type: standard` 并带 `Version:`。模块的总体设计仍固定为 `plans/<模块>/design.md`。不承诺的方向不落文档——写下来就是 `draft` 的 proposal，不写就是不做。

**10 类文档。**

| Type | 家 | 是什么 | 建议节 |
|---|---|---|---|
| `proposal` | `plans/` | 立项前对齐：为什么值得做、做成什么样算成功、有哪些候选路线。 | 背景、目标、成功判据、方案选项 |
| `spec` | `plans/` | 长期契约：做成什么样——字段、接口、验收标准；`done` 不是退役。模块的总体设计用固定形态 `plans/<模块>/design.md`（见「模块设计文档」）。 | 背景、范围、契约、验收标准、适用边界 |
| `plan` | `plans/` | 分几步做、做到哪了；`active` 时「未完成事项」是唯一活跃清单。 | 背景、步骤、未完成事项 |
| `survey` | `research/` | 一次性调研：问题、方法、结论与适用边界；结论必须能追到证据。 | 问题、方法与来源、结论、证据与出处、适用边界 |
| `evidence` | `research/` | 原始事实快照：什么时候、用什么命令、看到了什么。 | 采集内容、采集方式、适用边界 |
| `postmortem` | `research/` | 事故复盘：时间线、因果链、影响、预防与行动项。 | 事故概述、时间线、影响、因果链、预防、行动项 |
| `reference` | `research/` | 长期事实参考：持续维护的映射与导览；外部事实登记去 `docs/`。 | 事实映射、方法与来源、维护方式、适用边界 |
| `runbook` | `skills/` | 人向操作手册：前置条件、步骤、每步验证、失败恢复。 | 前置条件、步骤、验证、失败与恢复 |
| `skill` | `skills/` | Agent 按需加载的工作流：frontmatter 加步骤加边界。 | 步骤、边界 |
| `standard` | `docs/` | 现行标准与契约：设计规范、UI 设计系统、API/数据契约、编码约定、写作与排版约定；需要「现行第几版」的文档。 | 背景、适用范围、契约、版本与兼容、适用边界 |

「建议节」是骨架默认，不是机器配额：同族类型可按内容增删节，但不要把另一个家的事实搬进来；检查脚本不查节的完整性（见「适用边界」）。

**笔记（note）。** 决策因果住 `notes/{proposed|implemented|rejected}/[<category>/]yyyy-mm-dd-topic-title.md`（允许品类子目录，如 `architecture/`；`archived/` 扁平）；不带 `Type:` 行，头块两行：标题与 `Status:`。

```markdown
# Agent Note: <标题>

Status: <proposed | implemented | rejected — 一行原因>
```

`proposed` 尚未实现；`implemented` 已落地（记录决定了什么、否决了什么，与落地保持同步）；`rejected` 考虑过并否决——`—` 后的一行原因非空。正文四节（节名中英均可，语料惯例为英文）：Problem（问题）/ Decision 或 Proposal（决定或提案）/ Alternatives considered（备选方案）/ Consequences（后果），可加 Related（相关链接）；「备选方案」只记真实考虑过的选项与落选原因，禁编造。决定翻转不改写旧篇——新开一篇互链。

**3 行头块。** 类型化文档＝ `plans/`、`research/`、`skills/` 家内的 Markdown 文档，加上 `docs/` 下带 `Type: standard` 的标准（`README.md`、`AGENTS.md` 等目录说明文件与 `SKILL.md` 除外）；它们统一头块：标题 + 固定的 `Type:`、`Status:`、`Updated:` 三行（顺序固定），三行之后可追加项目自定义字段（如 `Version:`、`Owner:`、`Source:`），机器只校验三行及其取值、`standard` 与模块设计文档的 `Version:`，以及字段值是否残留 `<占位符>`。

```markdown
# <标题>

Type: <10 类之一>
Status: <该类型允许值>
Updated: yyyy-mm-dd
```

`standard` 在三行之后再加一行：

```markdown
Version: MAJOR.MINOR.PATCH
```

- 条件行两条：`Status: superseded` 必须带 `Superseded-by: <相对链接>`；归档件必须带 `Archived: yyyy-mm-dd`。
- `Updated:` 是最近一次实质改动日——改内容就改它；诚实性靠写作者，机器只查格式。
- 笔记、`skill` 与 `docs/` 自由知识不适用本头块——笔记用上面的两行形态，`SKILL.md` 用 frontmatter，`docs/` 自由知识无头块；技能目录内非 `SKILL.md` 的辅助文档按类型化文档处理（`Type:` 取 `skill`、不写 `Status:`、照填 `Updated:`），或整目录放 `.agents-raw` 免检。
- `docs/` 自由知识一旦在标题后的头块里写 `Type:`，就按类型化文档判；`standard` 是 `docs/` 下唯一合法的类型，其余类型仍应住 `.agents/` 的对应家。
- 字段值不得残留 `<占位符>`。

**状态与退役。**

| 族 | 允许的 Status | 流转 |
|---|---|---|
| proposal / spec / plan | draft / active / done / superseded | draft → active → done；被取代 → superseded |
| survey / evidence / reference | current / historical / superseded | current → historical（时效过去）；被取代 → superseded |
| postmortem | current / historical | 行动项未关 → current；全部关闭 → historical |
| runbook | current / superseded | 被取代 → superseded |
| skill | 无 Status（frontmatter 即身份） | — |
| standard | current / historical / superseded | current 是现行；不再用于新工作但保留参考 → historical；被取代 → superseded |

- `superseded` 是终态：不得迁出；要推翻就新建文档互链，`Superseded-by:` 指向取代者。
- **取代链必须终结在现行版本上**：从 `Superseded-by:` 逐跳读下去，必须落脚在一份类型化（有 `Type:`）、状态落在该族现行态、且未归档的文档——那是这个主题的现行版本。链断、成环、终结于笔记或 `docs/` 自由知识（无 `Type`/`Status`，链在那里不可判）、终结于归档件、终结于已退役态，都算错：旧文档留着不是问题，留着却解析不到现行版本才是问题。
- **现行态**（链终点判据用的那一份口径）：`proposal`/`plan` 的 `draft`/`active`；`spec` 的 `draft`/`active`/`done`（规格做完仍是权威）；`survey`/`evidence`/`reference`/`postmortem` 的 `current`；`runbook` 的 `current`；`standard` 的 `current`。其余取值都是历史：`plan` 做完就是历史，`research` 三类的 `historical` 是时效过去，`standard` 的 `historical` 是仅保留给存量或参考——它们可以出现在链上，但不能当链的终点。
- **一主题一现行承载点**：同一主题（如排版规范、写作约定、发布流程、UI 设计系统）同一时刻只有一份文档是现行版本。新的全局指导只有两种合法落法——原地改这份（`spec` 与 `standard` 的做法，历史在 git），或新开一份并由它取代旧的；两份都留着、都声称是规范，属违规。这条跨两根生效：`.agents/plans/<模块>/design.md` 与 `docs/<主题>.md` 不能同时声称是同一主题的现行承载点。它是纪律，机器判不出「两份是否同一主题」，见「适用边界」。
- `spec` 的 `done` 不是退役——规格是长期契约，后续变更原地改它并更新 `Updated:`；`done` 的 proposal / spec / plan 均留原家，不迁 `research/`。
- `standard` 的 `historical` 不是终态：它不再作为新工作依据，但仍可能被存量消费者引用；要重新启用就新建一份 `current` 的标准并互链，不改写旧篇。
- 退役顺序：先状态翻转；冷历史（不再维护、不再被引用）才归档；**永不删除**。
- 翻转状态是取代动作的一部分，不是事后清理：同批把「引用旧文并把它当现行依据」的文档一并改指，`Superseded-by:` 补上；只翻自己的状态、不改引用，等于把旧规则留在别人的正文里继续生效。
- `Version:` 归模块设计文档（`plans/<模块>/design.md`）与 `docs/` 标准；`Version` 记的是这份文档自己的契约演进，与包版本、与取代链互不相干。其余文档不要求，写了机器也不判。
- 写错类型：改 `Type:` 并按新家的命名规则移动文件，同批修入链；`Status` 由改这份文档的人随实质变更同批改，机器只校验取值。

### 模块设计文档

一个模块要有一份总体设计；知道模块名，就要能一步找到它，并且看得出它演进到哪一版。这件事用**固定路径加固定字段**做——不建注册表、不建 `INDEX.md`、不加第四个根。

- **位置与命名**：`.agents/plans/<模块>/design.md`。目录名是模块标识，kebab-case 或纯中文名都行（`plans/chat-bridge/design.md`、`plans/聊天桥接/design.md` 同效），文件名固定 `design.md`——固定名不随落笔日变，因此**免日期前缀**（与 `skills/<技能>/SKILL.md`、`RUNBOOK.md` 同族）；同目录下的计划、提案仍按 `yyyy-mm-dd-topic-title.md` 命名。
- **标题**：`#` 标题里必须出现模块标识，人话名随意——`# chat-bridge（聊天桥接）总体设计` 与 `# 聊天桥接（chat-bridge）总体设计` 都合法。路径承担稳定身份，标题承担可读的名字，两者指向同一个模块。
- **类型与状态**：`Type: spec`，状态按 spec 的取值（`done` 不是退役）。
- **版本**：头块加 `Version: MAJOR.MINOR.PATCH`，必填。这是**这份设计自己的版本**，与包版本、与取代链各管一件事：取代链回答「哪一份是现行」，`Version` 回答「这一份自己演进到哪」。MAJOR 是契约不兼容的变更，MINOR 是兼容的新增，PATCH 是澄清与改字。
- **怎么演进**：默认原地改、`Version` 递增、`Updated:` 改今天，历史在 git；只有模块被拆分、改名或整体重做时，才新建一份并让旧的翻 `superseded`（取代链照旧必须走到现行版本）。
- **怎么找**：目录即索引——`ls .agents/plans/*/design.md` 就是全部模块；`rg -n '^Version:' .agents/plans/*/design.md` 一次列出版本。不建索引文件，因为索引会和现实漂移，路径不会。
- **归属**：模块总体设计是单模块的内部契约，仍住 `.agents/`；跨模块、全项目、对外的标准住 `docs/`（见「docs 标准」）。两者不复制正文，同一主题只有一个现行承载点。

除模块设计外，`plans/` 的文档仍按 `yyyy-mm-dd-topic-title.md` 命名——日期表示落笔时点，对一份长期维护的设计没有意义，这个固定形态就是那个例外。

### docs 标准

一个项目会有跨模块、全项目共同遵守的设计标准（UI 设计系统、API/数据契约、编码约定、写作与排版约定）。它们面向所有读者，需要「现行第几版」的答案，住 `docs/`，类型是 `standard`。这件事同样用**固定类型字段加版本字段**做——不建 `docs/standards/` 目录、不建注册表、不建 `INDEX.md`。

- **位置与命名**：`docs/<主题>.md`，主题段 kebab-case 或纯中文名；不加日期前缀。需要多版本共存或对外 URL 稳定时，文件名可带版本，如 `docs/设计规范v1.2.md`、`docs/design-standard-v2.md`——文件名里的版本是人读标签，头块 `Version:` 是权威；文件名版本必须是头块版本的前缀（`v1.2` 对 `1.2.0`，`v2` 对 `2.0.0`）。
- **类型与状态**：`Type: standard`；`Status` 取 `current` / `historical` / `superseded`。`current` 是现行，`historical` 是仅保留给存量或参考，`superseded` 是终态且必须带 `Superseded-by:`。
- **版本**：头块必填 `Version: MAJOR.MINOR.PATCH`。语义与模块设计文档一致：MAJOR 是契约不兼容、MINOR 是兼容新增、PATCH 是澄清改字。默认原地改、`Version` 递增、`Updated:` 改今天，历史在 git；只有大版本线必须共存、主题被拆分/改名/整体重做时，才新建一份并让旧的翻 `superseded` 或 `historical`。
- **与模块设计的分工**：模块总体设计是单模块内部契约，住 `.agents/plans/<模块>/design.md`；跨模块、全项目、对外标准住 `docs/`。同一主题同一时刻只能有一个现行承载点；模块设计升级为全局标准时，新建 docs 标准并让旧 design.md 翻 `superseded` 指过来，或标准链接到 design.md，不复制正文。
- **怎么找**：目录即索引——`ls docs/` 与 `rg -l '^Type: standard$' docs/` 足以列出全部标准，`rg -n '^(Type|Status|Version|Updated):' docs/` 看它们的头块；不建索引文件，因为索引会漂移。
- **冻结**：`docs/` 自由知识没有 `Type:`，不参与本套状态机；它仍是当前版即唯一真相，改了直接改。只有需要「现行第几版」的标准才用 `standard`。

存量文档里已经在当标准用的，可以先用 `node .agents/tools/check-docs.mjs --suggest-standards` 只读列一遍候选：它按文件名关键词与旧头块线索提示，不会改写文件；确认后由人补 `Type: standard`、`Status:`、`Updated:` 与 `Version:`。一主题一现行承载点不因纳管而放松——同一主题若已有 `current` 标准，就改那一份，不再新建第二份。

### 规范格式（骨架）

**文件名与目录。**

- 目录名两种形态取一：kebab-case（小写字母、数字、连字符），或纯中文名（中文开头、可续数字、不含空格与标点）。`.agents/` 下五个家：`plans/`、`research/`、`notes/`、`skills/`、`archive/`。中文名便于人读写，英文名便于跨平台与终端；混用两种（如 `chat桥接`）与含空格、连字符的中文名一律算错。
- 日期型文档：`yyyy-mm-dd-topic-title.md`，日期取首次落笔日；主题段中英文均可。
- 固定型文件名：技能目录内 `SKILL.md`；人向操作手册 `RUNBOOK.md`；目录入口 `README.md`；模块总体设计 `plans/<模块>/design.md`（只在这一层，见「模块设计文档」）。
- `docs/` 文档：自由知识与标准都用主题名、无日期前缀——身份是主题，不是落笔时点；标准可带版本后缀（见「docs 标准」），自由知识不要求头块。
- 笔记：`notes/{lifecycle}/[<category>/]yyyy-mm-dd-topic-title.md`（`archived/` 扁平）。

**plan 族骨架（proposal / spec / plan）。** 以 plan 为例：

```markdown
# <标题>

Type: plan
Status: draft
Updated: yyyy-mm-dd

一句话说明：这份计划要交付什么。

## 背景

为什么现在做；依赖的前置事实与决策（相对链接）。

## 步骤

1. 动作 + 该步的可观察验证。

## 未完成事项

- [ ] 尚未做完的项；`Status: active` 时本节是这项工作唯一的活跃清单。
```

proposal 把「步骤 / 未完成事项」换成「目标 / 成功判据 / 方案选项」；spec 换成「范围 / 契约 / 验收标准 / 适用边界」——完整列见 10 类文档表。

**research 族骨架（survey / evidence / postmortem / reference）。** survey 用「问题 / 方法与来源 / 结论 / 证据与出处 / 适用边界」；evidence 用「采集内容 / 采集方式 / 适用边界」；postmortem 用「事故概述 / 时间线 / 影响 / 因果链 / 预防 / 行动项」；reference 用「事实映射 / 方法与来源 / 维护方式 / 适用边界」；runbook 与 skill 按 10 类文档表的建议节列。

`SKILL.md` 用 frontmatter：`name:` 取技能目录名，`description:` 写触发场景与关键词；正文为「步骤」「边界」两节。

**note 骨架。**

```markdown
# Agent Note: <标题>

Status: implemented

## Problem

动机要能脱离方案独立成立。

## Decision

用现在时描述已落地现实；`proposed` 的笔记本节用 `## Proposal`。

## Alternatives considered

- **<备选>**：为什么落选。只记真实考虑过的，禁编造。

## Consequences

影响、放弃的收益、后续要盯的点。

## Related

相关文档的相对链接（可选）。
```

**docs/ 自由知识骨架。**

```markdown
# <主题>

一句话说明：这份登记覆盖哪个仓外系统的哪些事实。

## <按主题分节>

当前版即唯一真相；改了直接改，历史在 git。引用一律相对链接，指向 `.agents/` 时写 `../.agents/…`。
```

**standard 骨架。**

```markdown
# <主题>（v<MAJOR.MINOR>）

Type: standard
Status: current
Updated: yyyy-mm-dd
Version: 1.0.0

一句话说明：这份标准约束什么、适用于谁。

## 背景

为什么需要这份标准；它取代了什么（相对链接）。

## 适用范围

适用与不适用；与模块设计文档的边界。

## 契约

必须遵守的规则、字段、接口、验收判据。

## 版本与兼容

MAJOR / MINOR / PATCH 各改什么；旧版本如何处置。

## 适用边界

机器不判、需要评审或纪律保证的部分。
```

`docs/` 自由知识无头块、无状态机；`standard` 有头块与轻量状态机。两者都不写计划、因果与证据——各归 `.agents/` 的家。

### 写作规则

- **一段一物理行**：每个自然段写成一行（靠编辑器软折行；表格、列表、代码块除外）——diff 干净、评审省力。
- **中英混排**：中文与英文、数字、行内代码之间加一个半角空格；中文用全角标点（，。；：！？（））。
- **禁 emoji**；直给结论。功能性符号只放行 `→`。
- **只写当前状态**：历史、过程、被否方案不进正文——分别去 git、笔记、`rejected/`。
- **明文：不设任何字数、篇幅、时效预算。** 没有最少行数、没有上限、没有复核周期；长度凭「写够合约、删掉推理记录与装饰」判断。机器不数行数，也不查 `Updated:` 的新鲜度。
- 一概念一词；新术语先在正文定义再用。

### 链接与检索

引用一律相对 Markdown 链接，目标必须存在（可机械校验）；正文不写裸路径。外部 URL 只作定位符：不保证可达、检查跳过、不触发抓取。

**用前先解析状态。** 全文检索不看头块，命中一篇不等于它是现行版本——默认检索面里 `superseded` 文档照常出现。所以把一份文档当依据之前，先读它标题后的头块：`docs/` 自由知识没有 `Type:`，当前文件即真相；`.agents/` 类型化文档与 `docs/` 标准有 `Type:`，按 `Status:` 解析——`superseded` 的按 `Superseded-by:` 追到终点再读，`historical` 只作存量/历史参考，`Archived:` 的按冷历史处理；不得把旧文内容当现行规则。头块就在标题之后几行，这个动作的成本几乎为零，漏掉它的代价是把旧规则当新规则执行。做同一件事的 agent 尤其要遵守这条：你读到的是文档，不是「最新版」。

禁全局 `INDEX.md`——目录即索引；检索用全文检索工具（下文配方以 `rg` 为例，无 `rg` 用等价工具按同参数替代）：

```bash
# 1. 全工作区检索（排除两个归档区）
rg --hidden -g '!.agents/archive/**' -g '!.agents/notes/archived/**' <关键词> .agents/ docs/

# 2. 只搜决策笔记（含 rejected，排除 archived）
rg --hidden -g '!.agents/notes/archived/**' <关键词> .agents/notes/

# 3. 按类型列文档（模式锚定文件头，避免命中正文骨架示例）
rg -U -l '\A#[^\n]*\n\nType: plan$' .agents/plans/

# 4. 按状态列文档（同样锚定文件头）
rg -U -l '\A#[^\n]*\n\nType: [a-z]+\nStatus: superseded$' .agents/ docs/

# 5. 找入链（归档前必跑：还有谁指向这篇）
rg -n '\]\([^)]*<目标文件名>' .agents/ docs/

# 6. 反查取代者（Superseded-by 只写单向，反向索引现算、不落盘）
rg -n '^Superseded-by:' .agents/ docs/ | rg -i '<关键词或文件名>'

# 7. 命中先看状态：列出命中，并把每篇的头块状态带出来
rg --hidden -g '!.agents/archive/**' -g '!.agents/notes/archived/**' -l '<关键词>' .agents/ docs/ \
  | while read -r f; do printf '%s\t' "$f"; head -10 "$f" | awk '/^(Type|Status|Version|Superseded-by):/{printf "%s ", $0} END{print ""}'; done

# 8. 列模块与设计文档版本（目录即索引；模块设计文档见「模块设计文档」）
rg -n '^Version:' .agents/plans/*/design.md

# 9. 列 docs 标准的状态与版本（目录即索引；标准见「docs 标准」）
rg -l '^Type: standard$' docs/ | while read -r f; do
  printf '%s\t' "$f"; head -12 "$f" | awk '/^(Status|Version|Updated):/{printf "%s ", $0} END{print ""}'
done
```

配方 6 与 7 都是粗筛：6 只看 `Superseded-by:` 这一行，7 只抽命中文件前 10 行的头块状态；判现行的权威仍是各自头块。仓库里 `superseded` 文档多到影响检索时，先问一句：为什么旧版本还没被归档或改干净——多数情况下该修的是取代链的终点，不是检索配方。

批量语料目录（外部文档镜像、采集数据）：`rg` 检索补一条 `-g '!<语料目录>/**'`；检查脚本用 `--exclude <语料目录>`（绝对路径的 exclude 按字面比较、经符号链接别名时不生效，见「配套脚本规格」的说明），或在目录内放空标记文件 `.agents-raw` 整目录豁免（见「配套脚本规格」的豁免清单）。

### 配套脚本规格

**位置与锚点。** 配套机器件只有一支脚本 `check-docs.mjs`：只用 Node 内置模块（Node ≥ 18），无依赖、不联网、不执行文档内代码。工作区根取**调用时的工作目录**，该目录须自身含 `.agents/` 或 `docs/` 目录——两者皆无时默认调用与诊断模式退出码 2，不自脚本位置、也不向父目录上溯（上溯会命中 `~/.agents` 一类无关祖先）。脚本文件位置不限（可搬出 `.agents/tools/`），但一律以调用目录为基准，故调用前先 `cd` 到工作区根。结构判定以根下的 `.agents/` 目录为锚（不以路径段）；`docs/` 的标准判定以根下 `docs/` 目录为锚。只有 `docs/` 时走 docs-only 模式：不跑 `.agents/` 结构组，仍跑编码预检、docs 标准头块与链接组，并在 stderr 与汇总行标注「结构组未执行：仅 docs/ 根」。每次调用先打印被检树，再列告警。

**调用与退出码。**

```bash
node .agents/tools/check-docs.mjs [路径…]                  # 报告模式：列发现，不失败
node .agents/tools/check-docs.mjs --strict [路径…]         # 严格模式：任一发现即失败
node .agents/tools/check-docs.mjs --health                 # 诊断：载荷、桥、AGENTS.md 合并态、docs 覆盖（只读）
node .agents/tools/check-docs.mjs --suggest-standards      # 诊断：列出 docs 标准候选与建议头块（只读）
```

| 退出码 | 含义 |
|---|---|
| 0 | 检查完成且未发现问题；非严格模式跑完即 0（发现问题在输出里逐条列出）；诊断模式（`--health` / `--suggest-standards`）正常跑完一律 0 |
| 1 | `--strict` 且发现至少一个问题；诊断模式不受 `--strict` 影响，不返回 1 |
| 2 | 无法完成检查——报告模式与 `--strict` 下为扫描面为空、路径不存在、根锚点缺失或内部错误；诊断模式下为根锚点缺失、内部错误或用法错误（诊断不接受路径参数）。任何模式都不得返回 0 |

退出码 0 在非严格模式下有歧义——它同时表示「无发现」与「有发现、已列出」。**任何读退出码的门禁必须带 `--strict`**；报告模式与两项诊断都是给人看的巡检面，不是判据面——诊断模式更弱，只列清单，不参与门禁。

扫描面：未给路径参数时取默认两根 `.agents/` 与 `docs/`（存在才扫，至少一个存在即合法根；两者皆无即退出码 2），默认两根与 `--exclude` 的相对值以工作区根（即调用目录）为基准；给出路径参数时以给出的路径为完整扫描面（不叠加默认），显式路径按调用目录解析——调用前先 `cd` 到工作区根，或传绝对路径；`--exclude <路径或 glob>` 从扫描面减去（归一后为空的值报用法错误，不静默空转）；绝对路径的 exclude 按字面比较，经符号链接别名（如 macOS 的 `/tmp` 与 `/private/tmp`）时不生效——传 realpath 后的路径，或改用相对路径。显式路径的扫描面内没有 `.agents/` 子树时，结构组不执行：注记走 stderr，且汇总行自带「结构组未执行」标注（只跑编码预检与链接组；扫描面内有 `docs/` 时另跑标准头块）。默认调用只有 `docs/` 时同样标注（docs-only 模式）。结构锚存在但 `.agents/` 下五个家（`plans/`、`research/`、`notes/`、`skills/`、`archive/`）一个都没有时同样注记「结构组无判定对象」——空 `.agents/` 会与完整树同形全绿，是已知的假绿形态。**扫描面只收 `.md`（大小写不敏感）**——`.mdx`、`.markdown` 不进面，宿主文档用这些扩展名时「全绿」不覆盖它们。非 git 环境同面工作（纯文件系统遍历）；符号链接按真实路径解析去重，不跟随指向扫描面外的链接。输出先给被检树（调用目录绝对路径 + 面描述），再逐条给「组号 + 文件：行号 + 判据」。汇总行在告警大于 0 时附组计数：`检查 N 篇 / 告警 M 条（组 0 a、组 1 b、组 2 c、组 3 d）`；无告警时仍是 `检查 N 篇 / 告警 0 条`。

**诊断模式（2.5 新增）。** `--health` 与 `--suggest-standards` 是两项只读诊断，回答「装得全不全」与「哪些存量文档已经在当标准用」。它们不改变默认扫描面，不参与 3 组检查，不受 `--strict` 影响，不写任何文件；正常一律退出码 0，只有根锚点缺失、内部错误或用法错误（如带路径参数）才返回 2。两者可以同时使用，同时给出时先输出 health、再输出 suggest；诊断模式不接受路径参数，先 `cd` 到工作区根。它们是诊断面，不是判据面。

- `--health`：打印工作区身份（调用目录绝对路径）、规范头（`.agents/README.md` 的首个非空行）、检查器自身信息（脚本头部声明的 Curia 版本、脚本 sha256 前 8 位与实际行数）、14 项载荷盘点（`.agents/GLOSSARY.md` 为推荐项，其余为必需项）、三条桥（`CLAUDE.md`、`.claude/skills`、`.codex/skills`）的状态、根 `AGENTS.md` 的合并态，以及 `docs/` 标准篇数与候选篇数。桥状态取 `symlink-ok` / `symlink-broken` / `symlink-other` / `real-file-pointer` / `real-file` / `real-dir` / `missing` / `other`：符号链接真解析到根 `AGENTS.md`（skills 桥为 `.agents/skills`）为 `symlink-ok`，目标存在但指向别处为 `symlink-other`，悬空链接为 `symlink-broken`，`CLAUDE.md` 是真实文件且前 20 行指向 `AGENTS.md` 为 `real-file-pointer`、否则为 `real-file`，真实目录为 `real-dir`，路径不存在为 `missing`，其余形态为 `other`。检查器本身可搬出 `.agents/tools/`（位置不限），此时载荷仍算齐全，health 会注明运行位置。`AGENTS.md` 合并态取 `merged`（含「一事实一归属」判据句，且「通用规则」「桥」「结构速览」三节均为 H2）/ `partial`（缺节或降为 H3）/ `not-merged`（文件不存在、无法读取或未含判据句）。
- `--suggest-standards`：只读列出 `docs/` 下的标准候选，逐篇给候选理由与一份建议头块（标题沿用原标题，`Type: standard`、`Status: current`、`Updated: <当天>`、`Version: 1.0.0`，由人确认后手动补齐）。理由是启发式线索：文件名含标准类关键词（规范、标准、design、spec、contract、契约、约定、指南、规则、边界、宪章、API、协议，大小写不敏感）、前 20 行有 `Updated:`/`Verified:`、前 20 行有 `Version:` 而尚无 `Type: standard`；位于 `docs/archive/` 的候选另附一条「先确认是否仍属现行」。候选与建议都不是判定——是否真的是标准、该给什么状态与版本由人决定；不写文件、不自动改写，误报与漏报都可能发生。

两项诊断只证明机械存在与候选形状：载荷文件在不在、桥是什么形态、`AGENTS.md` 有哪些节、`docs/` 里有多少篇带 `Type: standard`；桥是否真的连通各 CLI、载荷内容是否最新、候选是否真的是标准，仍归人工判断。权威始终是本规范与评审，不是诊断输出。

**编码预检 + 3 组检查（报告组号 0 至 3）。**

| # | 组 | 判据（命中即报） |
|---|---|---|
| 0 | 编码（预检） | 文件含无法按 UTF-8 解码的字节或 NUL 字节（检出 U+FFFD 替换字符或 NUL）——报，并注明其余判据不可信。 |
| 1 | 头块与生命周期 | 类型化文档（定义见「3 行头块」）必须有 `Type:`、`Status:`、`Updated:` 三行且顺序固定；Type 不在 10 类内、Status 不在该类型允许集内、`Updated:` 非 `yyyy-mm-dd`、字段值残留 `<占位符>`——报。`standard` 还必须带 `Version: MAJOR.MINOR.PATCH`；文件名含 `v<版本>` 时须是头块 `Version` 的前缀——报。`Status: superseded` 无 `Superseded-by:`——报；`Superseded-by:` 的裸路径形态（非 Markdown 链接）目标不存在——报（Markdown 链接形态的目标存在性归组 3）；`Superseded-by:` 的链未终结于现行态类型化文档——报（判据见「状态与退役」；四种形态：指向归档件、指向笔记或 `docs/` 自由知识等无 `Type` 头块的文档、成环、终点非现行态）；链可多跳，多跳不断链不报。模块设计文档（`plans/<模块>/design.md`）：`Type` 不是 `spec`、缺 `Version:` 行、`Version` 非 `MAJOR.MINOR.PATCH`、标题不含模块标识——报。活动笔记（`notes/` 下非 `archived/`）：标题后的第一个非空行必须是 `Status:`，取值与所在 lifecycle 目录一致；`rejected` 的 `—` 后原因为空——报；`notes/` 下不在 lifecycle 目录（proposed / implemented / rejected）的笔记——报。三个归档区（`.agents/archive/**`、`.agents/notes/archived/**`、`docs/archive/**`）中带类型头块的文档必须有 `Archived: yyyy-mm-dd` 行；目录入口页（`README.md`）与说明性文件不适用。 |
| 2 | 家与命名 | 按类型表判家：`.agents/` 下类型与家不符——报；`docs/` 下带类型头块但不是 `standard`——报（应住对应 `.agents/<home>/`）；`standard` 出现在 `.agents/` 下（非归档区）——报；面外（既不在 `.agents/` 也不在 `docs/`）带类型头块的文档（含 `standard`），扫描面内有 `.agents/` 结构锚时报，无锚时不判（避免误伤外部路径巡检）；日期型文档文件名不以 `yyyy-mm-dd-` 开头——报（只查 plans/research 家与 notes 活动区；`plans/<模块>/design.md` 是固定名，豁免）；`design.md` 出现在别处——报（模块设计文档只有这一个落点）；目录名既不合 kebab-case、也不是纯中文名（中文开头、可续数字、不含空格与标点）——报（只查 `.agents/` 子树）。 |
| 3 | 链接 | 相对 Markdown 链接目标不存在——报（只查行内 `[x](y)` 形态；引用式与脚注定义不查）；锚点、协议相对 `//` 与带 scheme 的外部 URL 跳过；扫描含归档区。**现行依据**（`plans/`、`skills/` 里带 `Type:` 且 `Status` 非 `superseded` 的文档，以及 `docs/` 下 `Status: current` 的 `standard`——讲「该怎么做」的那一类）的相对链接指向 `superseded` 文档——报，并指出该文档的现行版本；`research/`（某时点快照）、笔记、`docs/` 自由知识与归档区一律不判。 |

**不查清单（明示）。** 围栏代码块语言标注、标题层级跳级、表格竖线数、行尾空白、文件末尾换行、段落连排、中英空格、半角标点、emoji——九项机器不查、不进 `--strict`，责任归写作纪律与评审（细则见「写作规则」）：修法没有歧义、收益低，不值得占提交路径。

**类型枚举的两份。** 类型有两份表示：本规范的 10 类文档表（人读权威）与脚本内联的「类型 → 家 → 允许状态」表（机器读，约 20 行）；改类型表必须两份同批改——一致性靠人工纪律，无机内自检。

**豁免清单。**

- 目录级（任何组都不进）：`.git/`、`node_modules/`；`--exclude` 给出的路径；含空标记文件 `.agents-raw` 的目录（批量原始语料整目录豁免，仍应有一篇 survey 或 reference 说明它是什么、怎么采的）。
- 组级：组 0 编码预检对全部扫描文件生效；归档区只受归档头（组 1 的一部分）与链接（组 3）管辖（理由见「归档」）；组 1 只读头块（首个标题后连续的 `键: 值` 行块）；围栏与行内代码中的同形文本不参与任何组判定；但头块字段值按字面读、不剥行内代码——字段值不要包反引号（`` Updated: `2026-10-20` `` 会被报「非 yyyy-mm-dd」）；HTML 注释段本身不参与组 3 判定（注释段之外的可见文本照常判定；整行都在注释内的行整行豁免）。

**诚实条款。**

- **空集不冒充通过**：扫描面为 0 个文件时输出「未检查任何文件」并以退出码 2 结束——没检查不等于检查通过。
- **锚点断言只锚根**：默认调用下根锚点缺失必红（退出码 2）；显式路径的面内无 `.agents/` 子树、或默认调用只有 `docs/` 时，结构组不执行——注记走 stderr，汇总行自带「结构组未执行」标注。部分改名仍可能以退出码 0 加注记告终：不静默，但也不是失败。
- **只证明机械子集**：脚本通过不证明文档合规——节的完整性、事实真假、因果质量、时效新鲜度都不在机器判定面。
- **非 git 环境降级**：脚本不读 git；「永不删除」「`Updated:` 诚实性」「并行会话纪律」在无 git 时没有佐证，只剩纪律（见「适用边界」）。
- **异常必须响**：脚本内部错误、无输出、被中断——非零退出，不静默返回 0。

**钩子归采用方。** 规范不分发钩子、不自动安装任何东西；要挂提交拦截，采用方自己装一支 `.git/hooks/pre-commit`（git 静默忽略没有执行位的钩子，`chmod +x` 不能漏）：

```bash
printf '#!/bin/sh\nnode .agents/tools/check-docs.mjs --strict\n' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

装完验证：提交一份坏文档应被拦下。

注意：检查脚本读工作树、不读索引。不带路径的 `git commit` 提交的是索引版本——先 `git add` 坏版、改好工作树再提交，提交进去的仍是未经检查的版本，改完务必重新 `git add`；带路径的 `git commit -- <路径>` 提交的是工作树版本，与检查面一致。另：工作树里的未跟踪半成品也在扫描面内，会拦停与它无关的提交。

### 存量树只读纳管

存量项目采用本规范时：

1. 先登记纳入管理的根（默认 `.agents/` 与 `docs/`，或项目自己的既有目录），登记写在项目 `README.md` 或 `AGENTS.md` 里——纯文本，不建注册表文件。
2. 存量文档的原生生命周期、编号、命名保持原样；本规范的头块与 Status 只对纳入后新写、新改的文档生效。
3. 规则不回溯：不为合规批量补头块、改格式、修链接；不把「存量清理」设为采用前提。
4. 受机器消费的文件（被脚本、构建或注册表按路径引用的清单与生成物）不移动、不改名；要引用它们用链接，不动本体。
5. 检查脚本的默认面是 `.agents/` 与 `docs/`；登记的其他根不会自动进扫描面——在调用里显式传路径、用报告模式（不带 `--strict`）巡检。提交闸门只挂默认面——存量根传进 `--strict` 会被存量告警一直拦下（存量清理不设期限）；闸门启用前先把默认面内的既有告警修清或排除。纳入根内的存量文件不被特殊对待——要免检按目录写 `--exclude`，或用 `.agents-raw` 标记整目录豁免。「规则不回溯」指不为合规批量追改，不是机器不报。
6. 存量文档在下次被实质修改时自然补齐头块与格式——更替靠修订，不靠运动。
7. `docs/` 的存量设计规范默认按自由知识处理：不批量补 `Type: standard`，已有的 `docs/设计规范v1.2.md` 原样保留不算不合规；下次实质修改时再补 `Type:`、`Status:`、`Version:`。如果一份存量文档在标题后已经写了 `Type:` 但不是 `standard`，组 2 会报家归属——用报告模式巡检，按修订处置，不设清理期限。要盘点候选，跑 `--suggest-standards` 只读列一遍——它是提示，不是批量转换指令：不改写文件，确认后仍按下一次实质修改补头块。

### 归档

- **何时归档**：过时优先状态翻转；只有冷历史（不再维护、不再被引用）才归档。**永不删除。**
- **归档四步**（第 3、4 步缺一步都会留下断链或静默错链，真实事故形态；类型化文档第 2 步缺行由组 1 报出）：

1. **移动**：`.agents/` 的类型化文档移入 `.agents/archive/`（可加品类子目录）；笔记移入 `.agents/notes/archived/`（扁平放置）；`docs/` 标准可移入可选的 `docs/archive/`（可加品类子目录），`docs/` 自由知识也可原样移入。
2. **加行**：头块末尾加 `Archived: yyyy-mm-dd`；原有 `Type:`、`Status:` 保留，作为它退役前的身份。`docs/` 自由知识没有头块，不加行。
3. **重写自身相对链接**：逐条按目标归档后的位置重核——加品类子目录时深了一层，上行链接各补一层 `../`，同级链接对未同批归档的目标失效；平铺时深度不变，上行链接大体照旧，须改的是同级链接与指向同批归档件的链接。漏改时目标若仍存在会静默改指：加子目录时 `../README.md` 从 `archive/plans/` 解析到 `archive/README.md`，平铺时同级 `README.md` 从 `archive/` 解析到同一处。
4. **修入链**：全仓扫描指向旧路径的相对链接，同批改到新位置（配方见「链接与检索」第 5 条）。

只有 `.agents/archive/`、`.agents/notes/archived/` 与 `docs/archive/` 这三个固定落点享受归档机器豁免；其他名字（如 `docs/废弃文档/`）按普通主题目录处理，不强制迁移。

**检查面。** 三个归档区（`.agents/archive/`、`.agents/notes/archived/`、`docs/archive/`）不是豁免区——归档头（组 1）与链接（组 3）覆盖归档区，这正是四步第 3、4 步与类型化文档第 2 步的机器验证面。

**冻结。** 归档件永久不改；机器不做哈希封印，冻结靠纪律与评审——改动不会被机器发现（明示取舍，见「适用边界」）。

## 适用边界

- **机器只证明机械子集**：格式与链接可查；节的完整性、事实真假、结论质量、时效不查——检查全绿不等于文档合规。
- **诊断只证明机械存在与候选形状**：`--health` 能列出载荷在不在、桥的形态、`AGENTS.md` 的合并标记与 `docs/` 标准的篇数；桥是否真的被各 CLI 读到、载荷内容是否最新、候选是否真的是标准、是否与既有标准同一主题，都是人工判断。`--suggest-standards` 的候选来自文件名与头块启发式，误报与漏报都可能，不是验收结论。
- **明示取舍**：自检只留少数硬断言（空集必红、根锚点缺失必红（默认调用下）、异常非零），覆盖弱于逐规则负例夹具；风格面不设机器判据（见「不查清单」），漂移只剩写作纪律与评审；哈希封印不做，归档冻结与「永不删除」只剩纪律与评审，机器不能证明它们被遵守；复核周期与 `Updated:` 新鲜度检查不做，日期诚实性靠写作者；「读前解析状态」这条行为面同理——检查器能判链，判不了你有没有按链去读。
- **取代链只判指针与终点状态**：链能不能解析到一份现行态类型化文档，可判；「这份新文档是否真的该取代旧的」「新文替换了旧文的哪几条约束」是语义判定，机器不查，也没法从链推出来。
- **组 3 判的是事实不是意图**：「现行依据链到了被取代的文档」可判，「这段引用是被当成现行规则在用、还是只在说明沿革」判不了。所以该判据只覆盖 `plans/`、`skills/` 与 `docs/` 下 `current` 的 `standard`（讲「该怎么做」的那一类），`research/` 快照、笔记、`docs/` 自由知识与归档区一律不判——要写历史沿革，写进笔记或调研正文。
- **模块设计文档只证明形态**：路径、`Type`、`Version`、标题含模块标识可查；「每个模块都真的有一份」「这份设计是否覆盖了这个模块」机器不知道——没有注册表，就不存在「应该有的清单」，这既是不建索引的代价，也是它的好处（没有清单可漂移）。
- **docs 标准只证明形态**：家、`Type`、`Status`、`Version` 格式、文件名版本一致性与取代链可查；标准文件名的 kebab-case/纯中文形态是写作约定，机器只查文件名里的版本前缀，不查命名形态；「这份标准是否真的覆盖这个主题」「两份标准是否同一主题」「旧版是否仍适用于存量」机器不知道——靠适用范围一节与评审。`docs/` 自由知识没有状态，机器不判它是否过时。
- **一主题一现行承载点靠纪律**：机器不知道两份文档是不是同一个主题，也无法识别「两份都声称是规范」；这条只能靠评审与写作者。机器能保证的是：一旦你声明了取代关系，链的形态与终点可核。
- **类型表是上界不是配额**：10 类基于单仓实测的用量分布与真实 `docs/` 的标准落点；短文档为主的项目可以删减类型与建议节——规范只约束保留项的行为。
- **解耦判据只核验机械子集**：链接零命中与零依赖可跑；「不含宿主云环境、数据库、CI、域名或业务脚本名」靠评审，不做词表扫描——词表会变成又一套门禁。
- **归采用方**：钩子、CI、编辑器集成、评审流程、权限模型；存量迁移与批量修复不承诺（见「存量树只读纳管」）。
- **证据边界**：全部拦截数据来自单仓 12 天拦截台账的实测（2026-10-05 至 10-16、615 行）；其他仓的破坏面分布未知，格式规则的漏网率在无门禁条件下无法外推。
- 脚本面向 Node 运行环境；没有 Node 的项目可以只采用文本约定部分，检查脚本不构成采用前提。
