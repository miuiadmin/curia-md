# Curia 2.1 文档管理规范

一句话说明：Curia 2.1 是可移植的文档管理方案——两根、四句口诀定家、9 类文档、3 行头块、2 支轻量配套脚本，丢到任何项目都能用。

本规范正文以 `.agents/README.md` 为载荷载体（目录入口与总规格）：采用方进入 `.agents/` 第一眼看到的就是它。整段可拷进任何仓库、不必删改；它讲的是「怎么管理文档」，不是软件系统，配套检查脚本是轻量自检工具，不是门禁体系。

> 快速上手（第一次写文档）：1）选类型——查「9 类文档」表；2）选家——按「四句口诀」；3）抄对应骨架、落头块——见「规范格式（骨架）」；4）改完跑 `node .agents/tools/check-docs.mjs` 自检（可选）。

## 背景

Curia 2.1 回答一个问题：一个项目怎么管理自己的文档，才能让写文档的人与 Agent 不用先学一套平台。规范本体是纯 Markdown 约定与纯文本纪律——怎么写、放哪、怎么检索、怎么退役——配套只有一支轻量检查脚本与一支可选建档脚本。

它由单仓 12 至 15 天拦截台账的实测结论收敛而来（口径见「适用边界」）：保留持续拦截真实错误的机械面（格式、头块、链接、归档），不做从未触发的治理面（断言、Run、受保护交付、注册表、台账、自证矩阵）。被采用项目的根 `AGENTS.md` 引用本规范，约束其文档树。

## 范围

**是什么。** 一份关于「怎么管理文档」的指导方案：文档放哪（家）、是什么（类型）、长什么样（头块与骨架）、怎么引用与检索、过时了怎么退役。它约束文档树的写法与结构；它不是软件系统——没有运行时、服务、数据库、网络调用、权限模型、审批流、CI 或钩子，也不替你决定工作流程。

**不是什么。** 不是治理平台、不是流程引擎、不是门禁体系：配套检查脚本是轻量自检工具，只证明机械子集（见「配套脚本规格」与「适用边界」），不核验事实、不发布、不审批。

- 覆盖：两根布局与家归属；9 类文档与笔记的格式；写作、链接与检索规则；可抄进任何项目 `AGENTS.md` 的通用规则集；1 支检查脚本与 1 支可选建档脚本的规格；存量树只读纳管；归档四步；采用验收判据。
- 不覆盖：迁移工具与批量修复（见「存量树只读纳管」）；钩子与 CI 接线（归采用方，规范只给 `--strict` 与退出码）；时效复核与事实核验（明文不做，见「写作规则」）；多读者权限与对外发布面（另立系统，不属文档树）。

**解耦判据（可核验）。**

1. 分发文本可整段拷进任何仓库而不必删改（可跑）：不含指向宿主仓的爬升链接——`rg -n '\]\(\.\./(research|plans|notes|skills)/' <分发文本>` 零命中；把分发文本放进载荷树跑 `check-docs --strict`，链接组零报。
2. 脚本零依赖：只用 Node 内置模块，无 `package.json` 依赖、不联网。
3. 可移植运行：把 `.agents/`（规范、模板、脚本、文档）拷进无 git、无 `node_modules` 的目录，检查脚本照常运行并给出判定。
4. 无隐性前置：不装钩子、不接 CI、不用 git 也能完整使用；git 只增强佐证（历史、并行会话纪律），不是运行前提。

## 契约

### 模型本体

**两根，封顶两根。**

| 根 | 装什么 | 不装什么 |
|---|---|---|
| `.agents/` | 过程与制度：计划、调研、决策笔记、技能、归档。 | 外部事实登记、面向最终读者的发布内容。 |
| `docs/` | 知识与外部事实：仓外系统的登记与定义（资源 ID、字段映射、端点、协议）；当前版即唯一真相，无状态机，变更直接改、走评审。 | 计划与提案、决策因果、原始证据包。 |

受管面封顶这两根，不再设第三根；项目可以只启用其中一根。

**四句口诀（放哪的最后裁决）。**

1. 没做的 → `plans/`（proposal / spec / plan）
2. 做完的 → `research/`（survey / evidence / postmortem / reference）
3. 为什么 → `notes/`（决策因果，永远不进 research）
4. 过时的 → 状态翻转优先，冷历史进 `archive/` 封存；**永不删除**

补：可复用的干法 → `skills/`（skill / runbook）；外部事实 → 根 `docs/`。不承诺的方向不落文档——写下来就是 `draft` 的 proposal，不写就是不做。

**9 类文档。**

| Type | 家 | 是什么 | 建议节 |
|---|---|---|---|
| `proposal` | `plans/` | 立项前对齐：为什么值得做、做成什么样算成功、有哪些候选路线。 | 背景、目标、成功判据、方案选项 |
| `spec` | `plans/` | 长期契约：做成什么样——字段、接口、验收标准；`done` 不是退役。 | 背景、范围、契约、验收标准、适用边界 |
| `plan` | `plans/` | 分几步做、做到哪了；`active` 时「未完成事项」是唯一活跃清单。 | 背景、步骤、未完成事项 |
| `survey` | `research/` | 一次性调研：问题、方法、结论与适用边界；结论必须能追到证据。 | 问题、方法与来源、结论、证据与出处、适用边界 |
| `evidence` | `research/` | 原始事实快照：什么时候、用什么命令、看到了什么。 | 采集内容、采集方式、适用边界 |
| `postmortem` | `research/` | 事故复盘：时间线、因果链、影响、预防与行动项。 | 事故概述、时间线、影响、因果链、预防、行动项 |
| `reference` | `research/` | 长期事实参考：持续维护的映射与导览；外部事实登记去 `docs/`。 | 事实映射、方法与来源、维护方式、适用边界 |
| `runbook` | `skills/` | 人向操作手册：前置条件、步骤、每步验证、失败恢复。 | 前置条件、步骤、验证、失败与恢复 |
| `skill` | `skills/` | Agent 按需加载的工作流：frontmatter 加步骤加边界。 | 步骤、边界 |

「建议节」是骨架默认，不是机器配额：同族类型可按内容增删节，但不要把另一个家的事实搬进来；检查脚本不查节的完整性（见「适用边界」）。

**笔记（note）。** 决策因果住 `notes/{proposed|implemented|rejected}/[<category>/]yyyy-mm-dd-topic-title.md`（允许品类子目录，如 `architecture/`；`archived/` 扁平）；不带 `Type:` 行，头块两行：标题与 `Status:`。

```markdown
# Agent Note: <标题>

Status: <proposed | implemented | rejected — 一行原因>
```

`proposed` 尚未实现；`implemented` 已落地（记录决定了什么、否决了什么，与落地保持同步）；`rejected` 考虑过并否决——`—` 后的一行原因非空。正文四节（节名中英均可，语料惯例为英文）：Problem（问题）/ Decision 或 Proposal（决定或提案）/ Alternatives considered（备选方案）/ Consequences（后果），可加 Related（相关链接）；「备选方案」只记真实考虑过的选项与落选原因，禁编造。决定翻转不改写旧篇——新开一篇互链。

**3 行头块。** 类型化文档＝ `plans/`、`research/`、`skills/` 家内的 Markdown 文档（`README.md`、`AGENTS.md` 等目录说明文件与 `SKILL.md` 除外）；它们统一头块：标题 + 固定的 `Type:`、`Status:`、`Updated:` 三行（顺序固定），三行之后可追加项目自定义字段（如 `Owner:`、`Source:`），机器只校验三行及其取值，以及字段值是否残留 `<占位符>`。

```markdown
# <标题>

Type: <9 类之一>
Status: <该类型允许值>
Updated: yyyy-mm-dd
```

- 条件行两条：`Status: superseded` 必须带 `Superseded-by: <相对链接>`；归档件必须带 `Archived: yyyy-mm-dd`。
- `Updated:` 是最近一次实质改动日——改内容就改它；诚实性靠写作者，机器只查格式。
- 笔记、`skill` 与 `docs/` 文档不适用本头块——笔记用上面的两行形态，skill 用 frontmatter，`docs/` 无头块。
- 字段值不得残留 `<占位符>`。

**状态与退役。**

| 族 | 允许的 Status | 流转 |
|---|---|---|
| proposal / spec / plan | draft / active / done / superseded | draft → active → done；被取代 → superseded |
| survey / evidence / reference | current / historical / superseded | current → historical（时效过去）；被取代 → superseded |
| postmortem | current / historical | 行动项未关 → current；全部关闭 → historical |
| runbook | current / superseded | 被取代 → superseded |
| skill | 无 Status（frontmatter 即身份） | — |

- `superseded` 是终态：不得迁出；要推翻就新建文档互链，`Superseded-by:` 指向取代者。
- `spec` 的 `done` 不是退役——规格是长期契约，后续变更原地改它并更新 `Updated:`。
- 退役顺序：先状态翻转；冷历史（不再维护、不再被引用）才归档；**永不删除**。
- 写错类型：改 `Type:` 并按新家的命名规则移动文件，同批修入链；`Status` 由改这份文档的人随实质变更同批改，机器只校验取值。

### 规范格式（骨架）

**文件名与目录。**

- 目录名 kebab-case 英文；`.agents/` 下五个家：`plans/`、`research/`、`notes/`、`skills/`、`archive/`。
- 日期型文档：`yyyy-mm-dd-topic-title.md`，日期取首次落笔日；主题段中英文均可。
- 固定型文件名：技能目录内 `SKILL.md`；运维手册 `RUNBOOK.md`；目录入口 `README.md`。
- `docs/` 文档：kebab-case 主题名、无日期前缀——身份是主题，不是落笔时点。
- 笔记：`notes/{lifecycle}/[<category>/]yyyy-mm-dd-topic-title.md`（`archived/` 扁平）。

**plan 族骨架（proposal / spec / plan）。** 以 plan 为例：

```markdown
# <标题>

Type: plan
Status: draft
Updated: yyyy-mm-dd

一句话说明：这份计划要交付什么。

## 背景

为什么现在做；依赖的前置事实与决策（相对链接）。

## 步骤

1. 动作 + 该步的可观察验证。

## 未完成事项

- [ ] 尚未做完的项；`Status: active` 时本节是这项工作唯一的活跃清单。
```

proposal 把「步骤 / 未完成事项」换成「目标 / 成功判据 / 方案选项」；spec 换成「范围 / 契约 / 验收标准 / 适用边界」——完整列见 9 类文档表。

**research 族骨架（survey / evidence / postmortem / reference）。** 以 survey 为例：

```markdown
# <标题>

Type: survey
Status: current
Updated: yyyy-mm-dd

一句话说明：查了什么，最关键的结论是什么。

## 问题

调研要回答的具体问题。

## 方法与来源

怎么查的、查了哪些对象（路径、URL、版本）；方法要能被别人重跑。

## 结论

- 一条结论一句；结论必须能追到证据。

## 证据与出处

| 结论 | 证据 | 出处 |
|---|---|---|

## 适用边界

样本范围、未验证项、结论不成立的条件。
```

evidence 用「采集内容 / 采集方式 / 适用边界」；postmortem 用「事故概述 / 时间线 / 影响 / 因果链 / 预防 / 行动项」；reference 用「事实映射 / 方法与来源 / 维护方式 / 适用边界」；runbook 与 skill 按 9 类文档表的建议节列。

skill 用 frontmatter：`name:` 取技能目录名，`description:` 写触发场景与关键词；正文为「步骤」「边界」两节。

**note 骨架。**

```markdown
# Agent Note: <标题>

Status: implemented

## Problem

动机要能脱离方案独立成立。

## Decision

用现在时描述已落地现实；`proposed` 的笔记本节用 `## Proposal`。

## Alternatives considered

- **<备选>**：为什么落选。只记真实考虑过的，禁编造。

## Consequences

影响、放弃的收益、后续要盯的点。

## Related

相关文档的相对链接（可选）。
```

**docs/ 骨架。**

```markdown
# <主题>

一句话说明：这份登记覆盖哪个仓外系统的哪些事实。

## <按主题分节>

当前版即唯一真相；改了直接改，历史在 git。引用一律相对链接，指向 `.agents/` 时写 `../.agents/…`。
```

`docs/` 无头块、无状态机；不写计划、因果与证据——各归 `.agents/` 的家。

### 写作规则

- **一段一物理行**：每个自然段写成一行（靠编辑器软折行；表格、列表、代码块除外）——diff 干净、评审省力。
- **中英混排**：中文与英文、数字、行内代码之间加一个半角空格；中文用全角标点（，。；：！？（））。
- **禁 emoji**；直给结论。功能性符号只放行 `→`。
- **只写当前状态**：历史、过程、被否方案不进正文——分别去 git、笔记、`rejected/`。
- **明文：不设任何字数、篇幅、时效预算。** 没有最少行数、没有上限、没有复核周期；长度凭「写够合约、删掉推理记录与装饰」判断。机器不数行数，也不查 `Updated:` 的新鲜度。
- 一概念一词；新术语先在正文定义再用。

### 链接与检索

引用一律相对 Markdown 链接，目标必须存在（可机械校验）；正文不写裸路径。外部 URL 只作定位符：不保证可达、检查跳过、不触发抓取。

禁全局 `INDEX.md`——目录即索引；检索用全文检索工具（下文配方以 `rg` 为例，无 `rg` 用等价工具按同参数替代）：

```bash
# 1. 全工作区检索（排除两个归档区）
rg --hidden -g '!.agents/archive/**' -g '!.agents/notes/archived/**' <关键词> .agents/ docs/

# 2. 只搜决策笔记（含 rejected，排除 archived）
rg --hidden -g '!.agents/notes/archived/**' <关键词> .agents/notes/

# 3. 按类型列文档（模式锚定文件头，避免命中正文骨架示例）
rg -U -l '\A#[^\n]*\n\nType: plan$' .agents/plans/

# 4. 按状态列文档（同样锚定文件头）
rg -U -l '\A#[^\n]*\n\nType: [a-z]+\nStatus: superseded$' .agents/

# 5. 找入链（归档前必跑：还有谁指向这篇）
rg -n '\]\([^)]*<目标文件名>' .agents/ docs/
```

批量语料目录（外部文档镜像、采集数据）在项目里补一条 `-g '!<语料目录>/**'`，或在该目录放空标记文件 `.agents-raw` 整目录豁免（见「配套脚本规格」的豁免清单）。

### 通用 AGENTS 规则集

以下 8 条可直接抄进任何项目的根 `AGENTS.md`（路径与分支名按项目实际调整）：

```markdown
1. 一事实一归属：同一条事实只有一个家；别处引用用相对链接，不复制、不双写。
2. 先定家再落笔（四句口诀）：没做的进 `plans/`、做完的进 `research/`、为什么进 `notes/`、过时的翻状态或归档；可复用的干法进 `skills/`，外部事实进 `docs/`。
3. 非平凡变更同批写笔记：改变行为、结构、契约、流程、工具或格式的改动，同一批变更里新增或更新一篇 `notes/` 笔记；写前先搜（含 `rejected/`）。
4. 永不删除：过时文档优先翻状态；冷历史走归档四步——移动、`Archived:` 行、重写自身相对链接、修入链。
5. 引用一律相对 Markdown 链接，目标必须存在；禁全局 `INDEX.md`，检索用全文检索工具（`rg` 或等价）。
6. 写作格式：一段一物理行；中英之间加一个半角空格；中文全角标点；禁 emoji；只写当前状态。
7. 并行会话纪律：动手前 `git status`；只精确暂存自己的路径（禁 `git add -A` / `git add .`）；提交带显式路径（`git commit -- <自己的路径…>`）；推送前 `git log origin/main..HEAD` 确认推送范围；别人的未跟踪与已改文件一律不碰。
8. 改动文档后跑检查：`node .agents/tools/check-docs.mjs`（读工作树，无需先 `git add`）；提交把关用 `--strict`，可自挂钩子；装不装钩子归项目自定，本条不是提交硬门槛。
```

### 配套脚本规格

**位置与依赖。** 脚本住 `.agents/tools/`（避开目标仓根 `scripts/` 的命名空间碰撞）：`check-docs.mjs`（检查）与 `new-doc.mjs`（建档，可选）。只用 Node 内置模块（Node ≥ 18），无依赖、不联网、不执行文档内代码。配套机器件只含这两支脚本——不含钩子、台账、注册表 JSON、自证矩阵。

**调用与退出码。**

```bash
node .agents/tools/check-docs.mjs [路径…]            # 报告模式：列发现，不失败
node .agents/tools/check-docs.mjs --strict [路径…]   # 严格模式：任一发现即失败
```

| 退出码 | 含义 |
|---|---|
| 0 | 检查完成且未发现问题；非严格模式跑完即 0（发现问题在输出里逐条列出） |
| 1 | `--strict` 且发现至少一个问题 |
| 2 | 无法完成检查——扫描面为空、路径不存在、内部错误；两种模式都不得返回 0 |

扫描面：未给路径参数时取默认两根 `.agents/` 与 `docs/`（存在才扫），默认两根与 `--exclude` 的相对值按脚本位置（工作区根）解析，与调用时的工作目录无关；给出路径参数时以给出的路径为完整扫描面（不叠加默认），显式路径按调用目录解析——调用前先 `cd` 到工作区根，或传绝对路径；`--exclude <路径或 glob>` 从扫描面减去、`--skip <组号,…>` 跳过指定组（如纯英文项目跳过第 7、8 组）。非 git 环境同面工作（纯文件系统遍历）；符号链接按真实路径解析去重，不跟随指向扫描面外的链接。输出逐条给「组号 + 文件：行号 + 判据」。

**10 组检查（组 0 编码预检 + 组 1 至 9）。**

| # | 组 | 判据（命中即报） |
|---|---|---|
| 0 | 编码 | 文件含无法按 UTF-8 解码的字节（检出 U+FFFD 替换字符）——报，并注明其余判据不可信。 |
| 1 | 头块 | 类型化文档（定义见「3 行头块」）必须有 `Type:`、`Status:`、`Updated:` 三行且顺序固定；Type 不在 9 类内、Status 不在该类型允许集内、`Updated:` 非 `yyyy-mm-dd`、字段值残留 `<占位符>`——报。 |
| 2 | 状态与取代 | `Status: superseded` 无 `Superseded-by:`——报；`Superseded-by:` 的裸路径形态（非 Markdown 链接）目标不存在——报；Markdown 链接形态的目标存在性归第 9 组。 |
| 3 | 笔记头 | 活动笔记（`notes/` 下非 `archived/`）：标题后的第一个非空行必须是 `Status:`，取值与所在 lifecycle 目录一致；`rejected` 的 `—` 后原因为空——报；`notes/` 下不在 lifecycle 目录（proposed / implemented / rejected）的笔记——报。 |
| 4 | 归档头 | 两个归档区（`.agents/archive/**` 与 `.agents/notes/archived/**`）中带类型头块的文档必须有 `Archived: yyyy-mm-dd` 行；目录入口页（`README.md`）与说明性文件不适用。 |
| 5 | 家与命名 | `.agents/` 下类型与家不符——报；日期型文档文件名不以 `yyyy-mm-dd-` 开头——报；目录名不合 kebab-case（小写字母、数字、连字符）——报。 |
| 6 | 段落 | 正文中连续两行及以上自然段文本（未用空行分隔）——报。 |
| 7 | 中英空格 | 中文与拉丁字母、数字、行内代码相邻处缺半角空格——报（每行只报第一处；行内代码内部、围栏内、URL 内不查）。 |
| 8 | 标点与符号 | 中文语境的半角标点，即 `,`、`;`、`:`、`!`、`?`、`(`、`)`——报；emoji——报（半角标点与 emoji 每行各只报第一处）。 |
| 9 | 链接 | 相对 Markdown 链接目标不存在——报；锚点与外部 URL 跳过；扫描含归档区。 |

**不查的样式项（明示）。** 围栏代码块语言标注、标题层级跳级、表格竖线数、行尾空白、文件末尾换行——这五项是纯样式或已被编辑器与 `git diff --check` 覆盖，写进「写作规则」作指引，机器不查、不进 `--strict`。理由：纯样式项在 `--strict` 下会拦提交，而它们的修法没有歧义、收益也低，不值得占提交路径。

**类型枚举的两份与自检。** 类型有两份表示：本规范的 9 类文档表（人读权威）与脚本内联的「类型 → 家 → 允许状态」表（机器读，约 20 行）。一致性要求：脚本启动时读 `.agents/templates/*.md` 的文件名集合，与内联枚举比对——不一致即报配置错误（退出码 2）；改类型表必须同批改模板目录与脚本。模板文件是骨架实物，文件名即类型键。

**豁免清单。**

- 目录级（任何组都不进）：`.git/`、`node_modules/`；`--exclude` 给出的路径；含空标记文件 `.agents-raw` 的目录（批量原始语料整目录豁免，仍应有一篇 survey 或 reference 说明它是什么、怎么采的）；`.agents/templates/` 与 `.agents/examples/`（骨架实物与示例含占位符、不落各自的家，整目录豁免）。
- 组级：归档区只受第 4、9 组管辖（理由见「归档」）；组 1/2/4 只读头块（首个标题后连续的 `键: 值` 行块）；围栏与行内代码中的同形文本不参与任何组判定；HTML 注释段本身不参与第 6 至 9 组判定（注释段之外的可见文本照常判定；整行都在注释内的行整行豁免）。
- 组级：第 6 组的「一段一行」不适用于文档头块（首个标题后连续的 `键: 值` 字段行，至第一个空行为止）与 YAML frontmatter 块，判定从两者之后开始；也不适用于表格、列表、代码块、引用块、setext 下划线行与引用式链接（含脚注）定义行；第 7、8 组不查围栏内、行内代码内部与 YAML frontmatter 块（元数据不是正文，其中的半角逗号是 YAML 语法；头块字段的值是散文，照查）。

**诚实条款。**

- **空集不冒充通过**：扫描面为 0 个文件时输出「未检查任何文件」并以退出码 2 结束——没检查不等于检查通过。同理，扫描面内所有适用组都被 `--skip` 跳过时输出「0 条判据可执行」并退出码 2——没有可执行的判据不等于通过。
- **只证明机械子集**：脚本通过不证明文档合规——节的完整性、事实真假、因果质量、时效新鲜度都不在机器判定面。
- **非 git 环境降级**：脚本不读 git；「永不删除」「`Updated:` 诚实性」「并行会话纪律」在无 git 时没有佐证，只剩纪律（见「适用边界」）。
- **异常必须响**：脚本内部错误、无输出、被中断——非零退出，不静默返回 0。

**行数预算（设计指引，可核验）。** 两支脚本合计目标 ≤ 500 行；任一支超过 600 行，必须在脚本头注释写明理由。核验命令：`wc -l .agents/tools/*.mjs`。目标不是硬线——为修真实缺陷而小幅超出时在提交说明写明即可；硬线只有单支 600 行。

**建档脚本（可选）。** `node .agents/tools/new-doc.mjs --type <9 类之一> --topic <topic>`：按类型生成骨架（标题、3 行头块、一句话说明、建议节标题）并计算目标路径（家 + 该类型的命名规则：日期型或固定名）；只创建一个新文件、拒绝覆盖已存在文件、不联网。不装它不影响规范成立——骨架在「规范格式」里可以手抄。

**钩子归采用方。** 规范不分发钩子、不自动安装任何东西；要挂提交拦截，采用方自己写一行 pre-commit：

```bash
node .agents/tools/check-docs.mjs --strict
```

### 存量树只读纳管

存量项目采用本规范时：

1. 先登记纳入管理的根（默认 `.agents/` 与 `docs/`，或项目自己的既有目录），登记写在项目 `README.md` 或 `AGENTS.md` 里——纯文本，不建注册表文件。
2. 存量文档的原生生命周期、编号、命名保持原样；本规范的头块与 Status 只对纳入后新写、新改的文档生效。
3. 规则不回溯：不为合规批量补头块、改格式、修链接；不把「存量清理」设为采用前提。
4. 受机器消费的文件（被脚本、构建或注册表按路径引用的清单与生成物）不移动、不改名；要引用它们用链接，不动本体。
5. 检查脚本的默认面是 `.agents/` 与 `docs/`（存在才扫）；登记的其他根不会自动进扫描面——在调用里显式传路径、用报告模式（不带 `--strict`）巡检。提交闸门只挂默认面——存量根传进 `--strict` 会被存量告警一直拦下（存量清理不设期限）；闸门启用前先把默认面内的既有告警修清或排除。纳入根内的存量文件不被特殊对待——要免检按目录写 `--exclude`，或用 `.agents-raw` 标记整目录豁免。「规则不回溯」指不为合规批量追改，不是机器不报。
6. 存量文档在下次被实质修改时自然补齐头块与格式——更替靠修订，不靠运动。

### 归档

- **何时归档**：过时优先状态翻转；只有冷历史（不再维护、不再被引用）才归档。**永不删除。**
- **归档四步**（缺一步都会留下断链，真实事故形态）：

1. **移动**：类型化文档移入 `.agents/archive/`（可加品类子目录）；笔记移入 `.agents/notes/archived/`（扁平放置）。
2. **加行**：头块末尾加 `Archived: yyyy-mm-dd`；原有 `Type:`、`Status:` 保留，作为它退役前的身份。
3. **重写自身相对链接**：归档件深了一层，链接基准随之改变——指向同批归档件的改指归档区，其余改指原位置。
4. **修入链**：全仓扫描指向旧路径的相对链接，同批改到新位置（配方见「链接与检索」第 5 条）。

**检查面。** 归档区不是豁免区——第 4 组（归档头）与第 9 组（链接）覆盖归档区，这正是四步第 2 至 4 步的机器验证面；写作与格式组（第 6、7、8 组）不查归档件：冻结件永不修改，查出来也无法处置。

**冻结。** 归档件永久不改；机器不做哈希封印，冻结靠纪律与评审——改动不会被机器发现（明示取舍，见「适用边界」）。

## 验收标准（实现方验收用，不构成采用方义务）

以下判据逐条可跑；`check-docs` 指 `.agents/tools/check-docs.mjs`。负例三连、归档断链复现与模板增删自检是夹具级验收，细节归实现方文档，本节只留采用方可直接用的判据。

1. **空集断言**：`mkdir -p /tmp/empty-docs && node .agents/tools/check-docs.mjs --strict /tmp/empty-docs` → 输出「未检查任何文件」，退出码 2。
2. **正例**：在含 9 份模板与 `tools/` 的 `.agents/`（如载荷树或载荷生成的仓库）里按 9 类各生成一篇骨架后跑 `node .agents/tools/check-docs.mjs --strict` → 退出码 0。
3. **零依赖**：`rg -n "from ['\"]|require\(|import\(" .agents/tools/*.mjs` → 只应出现 `node:` 前缀的内置模块名；脚本目录无 `package.json` 依赖。
4. **可移植**：把 `.agents/` 拷进无 git、无 `node_modules` 的临时目录，跑第 2 条命令 → 与源目录同一判定。
5. **行数**：`wc -l .agents/tools/*.mjs` → 合计（尾行）目标 ≤ 500 行，超出时在提交说明写明增量理由；任一支硬线上限 600 行，超出须在脚本头注释写明理由。
6. **建档脚本**：`node .agents/tools/new-doc.mjs --type plan --topic sample` → 生成 `.agents/plans/<日期>-sample.md`（含 3 行头块与建议节）；对已存在目标拒绝覆盖（退出码非 0）。

## 适用边界

- **机器只证明机械子集**：格式与链接可查；节的完整性、事实真假、结论质量、时效不查——检查全绿不等于文档合规。
- **明示取舍**：自检被砍到两条硬断言（空集必红、异常非零），覆盖弱于逐规则负例夹具；哈希封印不做，归档冻结与「永不删除」只剩纪律与评审，机器不能证明它们被遵守；复核周期与 `Updated:` 新鲜度检查不做，日期诚实性靠写作者。
- **类型表是上界不是配额**：9 类基于单仓 12 至 15 天用量分布；短文档为主的项目可以删减类型与建议节——规范只约束保留项的行为。
- **中文写作组不适用于纯英文项目**：第 7、8 组按语言场景用 `--skip` 关掉。
- **解耦判据只核验机械面**：链接零命中与零依赖可跑；「不出现宿主云环境、数据库、CI、域名或业务脚本名」靠评审，不做词表扫描——词表会变成又一套门禁。
- **归采用方**：钩子、CI、编辑器集成、评审流程、权限模型；存量迁移与批量修复不承诺（见「存量树只读纳管」）。
- **证据边界**：全部拦截数据来自单仓 12 至 15 天窗口的实测（口径：单仓 12 至 15 天窗口实测）；其他仓的破坏面分布未知，格式规则的漏网率在无门禁条件下无法外推。
- 脚本面向 Node 运行环境；没有 Node 的项目可以只采用文本约定部分，检查脚本不构成采用前提。
