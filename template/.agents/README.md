# Curia 2.2 文档管理规范

一句话说明：Curia 2.2 是可移植的文档管理方案——两根、四句口诀定家、9 类文档、3 行头块、1 支轻量配套脚本，丢到任何项目都能用。

本规范正文以 `.agents/README.md` 为载荷载体（目录入口与总规格）：采用方进入 `.agents/` 第一眼看到的就是它。整段可拷进任何仓库、不必删改；它讲的是「怎么管理文档」，不是软件系统，配套检查脚本是轻量自检工具，不是门禁体系。

> 快速上手（第一次写文档）：1）选类型——查「9 类文档」表；2）选家——按「四句口诀」；3）抄对应骨架、落头块——见「规范格式（骨架）」；4）改完跑 `node .agents/tools/check-docs.mjs` 自检（可选）。

## 背景

Curia 2.2 回答一个问题：一个项目怎么管理自己的文档，才能让写文档的人与 Agent 不用先学一套平台。规范本体是纯 Markdown 约定与纯文本纪律——怎么写、放哪、怎么检索、怎么退役——配套只有一支轻量检查脚本。

它由单仓 12 天拦截台账的实测结论收敛而来（口径见「适用边界」）：保留持续拦截真实错误的机械子集（头块与生命周期、家与命名、链接），不做从未触发的治理面（断言、Run、受保护交付、注册表、台账、自证矩阵）。被采用项目的根 `AGENTS.md` 引用本规范，约束其文档树。

## 范围

**是什么。** 一份关于「怎么管理文档」的指导方案：文档放哪（家）、是什么（类型）、长什么样（头块与骨架）、怎么引用与检索、过时了怎么退役。它约束文档树的写法与结构；它不是软件系统——没有运行时、服务、数据库、网络调用、权限模型、审批流、CI 或钩子，也不替你决定工作流程。

**不是什么。** 不是治理平台、不是流程引擎、不是门禁体系：配套检查脚本是轻量自检工具，只证明机械子集（见「配套脚本规格」与「适用边界」），不核验事实、不发布、不审批。

- 覆盖：两根布局与家归属；9 类文档与笔记的格式；写作、链接与检索规则；1 支检查脚本的规格；存量树只读纳管；归档四步。
- 不覆盖：迁移工具与批量修复（见「存量树只读纳管」）；钩子与 CI 接线（归采用方，规范只给 `--strict` 与退出码）；时效复核与事实核验（明文不做，见「写作规则」）；多读者权限与对外发布面（另立系统，不属文档树）。

**解耦判据（可核验）。**

1. 分发文本可整段拷进任何仓库：不含指向宿主仓的爬升链接（`rg -n '\]\(\.\.' <分发文本>` 零命中），放进载荷树跑 `check-docs --strict`，链接零报。
2. 脚本零依赖：只用 Node 内置模块，不联网。
3. 可移植运行：把 `.agents/`（规范、脚本、文档）拷进无 git、无 `node_modules` 的目录，检查脚本照常运行并给出判定。
4. 无隐性前置：不装钩子、不接 CI、不用 git 也能完整使用。

## 契约

### 模型本体

**两根，封顶两根。**

| 根 | 装什么 | 不装什么 |
|---|---|---|
| `.agents/` | 过程与制度：计划、调研、决策笔记、技能、归档。 | 外部事实登记、面向最终读者的发布内容。 |
| `docs/` | 知识与外部事实：仓外系统的登记与定义（资源 ID、字段映射、端点、协议）；当前版即唯一真相，无状态机，变更直接改、走评审。 | 计划与提案、决策因果、原始事实快照。 |

受管面封顶这两根，不再设第三根；项目可以只启用其中一根。

**四句口诀（放哪的最后裁决）。**

1. 没做的 → `plans/`（proposal / spec / plan）
2. 做完的 → `research/`（survey / evidence / postmortem / reference）
3. 为什么 → `notes/`（决策因果，永远不进 research）
4. 过时的 → 状态翻转优先，冷历史进 `archive/` 封存；**永不删除**

补：可复用的干法 → `skills/`（skill / runbook）；外部事实 → 根 `docs/`。不承诺的方向不落文档——写下来就是 `draft` 的 proposal，不写就是不做。

**9 类文档。**

| Type | 家 | 是什么 | 建议节 |
|---|---|---|---|
| `proposal` | `plans/` | 立项前对齐：为什么值得做、做成什么样算成功、有哪些候选路线。 | 背景、目标、成功判据、方案选项 |
| `spec` | `plans/` | 长期契约：做成什么样——字段、接口、验收标准；`done` 不是退役。 | 背景、范围、契约、验收标准、适用边界 |
| `plan` | `plans/` | 分几步做、做到哪了；`active` 时「未完成事项」是唯一活跃清单。 | 背景、步骤、未完成事项 |
| `survey` | `research/` | 一次性调研：问题、方法、结论与适用边界；结论必须能追到证据。 | 问题、方法与来源、结论、证据与出处、适用边界 |
| `evidence` | `research/` | 原始事实快照：什么时候、用什么命令、看到了什么。 | 采集内容、采集方式、适用边界 |
| `postmortem` | `research/` | 事故复盘：时间线、因果链、影响、预防与行动项。 | 事故概述、时间线、影响、因果链、预防、行动项 |
| `reference` | `research/` | 长期事实参考：持续维护的映射与导览；外部事实登记去 `docs/`。 | 事实映射、方法与来源、维护方式、适用边界 |
| `runbook` | `skills/` | 人向操作手册：前置条件、步骤、每步验证、失败恢复。 | 前置条件、步骤、验证、失败与恢复 |
| `skill` | `skills/` | Agent 按需加载的工作流：frontmatter 加步骤加边界。 | 步骤、边界 |

「建议节」是骨架默认，不是机器配额：同族类型可按内容增删节，但不要把另一个家的事实搬进来；检查脚本不查节的完整性（见「适用边界」）。

**笔记（note）。** 决策因果住 `notes/{proposed|implemented|rejected}/[<category>/]yyyy-mm-dd-topic-title.md`（允许品类子目录，如 `architecture/`；`archived/` 扁平）；不带 `Type:` 行，头块两行：标题与 `Status:`。

```markdown
# Agent Note: <标题>

Status: <proposed | implemented | rejected — 一行原因>
```

`proposed` 尚未实现；`implemented` 已落地（记录决定了什么、否决了什么，与落地保持同步）；`rejected` 考虑过并否决——`—` 后的一行原因非空。正文四节（节名中英均可，语料惯例为英文）：Problem（问题）/ Decision 或 Proposal（决定或提案）/ Alternatives considered（备选方案）/ Consequences（后果），可加 Related（相关链接）；「备选方案」只记真实考虑过的选项与落选原因，禁编造。决定翻转不改写旧篇——新开一篇互链。

**3 行头块。** 类型化文档＝ `plans/`、`research/`、`skills/` 家内的 Markdown 文档（`README.md`、`AGENTS.md` 等目录说明文件与 `SKILL.md` 除外）；它们统一头块：标题 + 固定的 `Type:`、`Status:`、`Updated:` 三行（顺序固定），三行之后可追加项目自定义字段（如 `Owner:`、`Source:`），机器只校验三行及其取值，以及字段值是否残留 `<占位符>`。

```markdown
# <标题>

Type: <9 类之一>
Status: <该类型允许值>
Updated: yyyy-mm-dd
```

- 条件行两条：`Status: superseded` 必须带 `Superseded-by: <相对链接>`；归档件必须带 `Archived: yyyy-mm-dd`。
- `Updated:` 是最近一次实质改动日——改内容就改它；诚实性靠写作者，机器只查格式。
- 笔记、`skill` 与 `docs/` 文档不适用本头块——笔记用上面的两行形态，`SKILL.md` 用 frontmatter，`docs/` 无头块；技能目录内非 `SKILL.md` 的辅助文档按类型化文档处理（`Type:` 取 `skill`、不写 `Status:`、照填 `Updated:`），或整目录放 `.agents-raw` 免检。
- 字段值不得残留 `<占位符>`。

**状态与退役。**

| 族 | 允许的 Status | 流转 |
|---|---|---|
| proposal / spec / plan | draft / active / done / superseded | draft → active → done；被取代 → superseded |
| survey / evidence / reference | current / historical / superseded | current → historical（时效过去）；被取代 → superseded |
| postmortem | current / historical | 行动项未关 → current；全部关闭 → historical |
| runbook | current / superseded | 被取代 → superseded |
| skill | 无 Status（frontmatter 即身份） | — |

- `superseded` 是终态：不得迁出；要推翻就新建文档互链，`Superseded-by:` 指向取代者。
- `spec` 的 `done` 不是退役——规格是长期契约，后续变更原地改它并更新 `Updated:`；`done` 的 proposal / spec / plan 均留原家，不迁 `research/`。
- 退役顺序：先状态翻转；冷历史（不再维护、不再被引用）才归档；**永不删除**。
- 写错类型：改 `Type:` 并按新家的命名规则移动文件，同批修入链；`Status` 由改这份文档的人随实质变更同批改，机器只校验取值。

### 规范格式（骨架）

**文件名与目录。**

- 目录名 kebab-case 英文；`.agents/` 下五个家：`plans/`、`research/`、`notes/`、`skills/`、`archive/`。
- 日期型文档：`yyyy-mm-dd-topic-title.md`，日期取首次落笔日；主题段中英文均可。
- 固定型文件名：技能目录内 `SKILL.md`；人向操作手册 `RUNBOOK.md`；目录入口 `README.md`。
- `docs/` 文档：kebab-case 主题名、无日期前缀——身份是主题，不是落笔时点。
- 笔记：`notes/{lifecycle}/[<category>/]yyyy-mm-dd-topic-title.md`（`archived/` 扁平）。

**plan 族骨架（proposal / spec / plan）。** 以 plan 为例：

```markdown
# <标题>

Type: plan
Status: draft
Updated: yyyy-mm-dd

一句话说明：这份计划要交付什么。

## 背景

为什么现在做；依赖的前置事实与决策（相对链接）。

## 步骤

1. 动作 + 该步的可观察验证。

## 未完成事项

- [ ] 尚未做完的项；`Status: active` 时本节是这项工作唯一的活跃清单。
```

proposal 把「步骤 / 未完成事项」换成「目标 / 成功判据 / 方案选项」；spec 换成「范围 / 契约 / 验收标准 / 适用边界」——完整列见 9 类文档表。

**research 族骨架（survey / evidence / postmortem / reference）。** survey 用「问题 / 方法与来源 / 结论 / 证据与出处 / 适用边界」；evidence 用「采集内容 / 采集方式 / 适用边界」；postmortem 用「事故概述 / 时间线 / 影响 / 因果链 / 预防 / 行动项」；reference 用「事实映射 / 方法与来源 / 维护方式 / 适用边界」；runbook 与 skill 按 9 类文档表的建议节列。

`SKILL.md` 用 frontmatter：`name:` 取技能目录名，`description:` 写触发场景与关键词；正文为「步骤」「边界」两节。

**note 骨架。**

```markdown
# Agent Note: <标题>

Status: implemented

## Problem

动机要能脱离方案独立成立。

## Decision

用现在时描述已落地现实；`proposed` 的笔记本节用 `## Proposal`。

## Alternatives considered

- **<备选>**：为什么落选。只记真实考虑过的，禁编造。

## Consequences

影响、放弃的收益、后续要盯的点。

## Related

相关文档的相对链接（可选）。
```

**docs/ 骨架。**

```markdown
# <主题>

一句话说明：这份登记覆盖哪个仓外系统的哪些事实。

## <按主题分节>

当前版即唯一真相；改了直接改，历史在 git。引用一律相对链接，指向 `.agents/` 时写 `../.agents/…`。
```

`docs/` 无头块、无状态机；不写计划、因果与证据——各归 `.agents/` 的家。

### 写作规则

- **一段一物理行**：每个自然段写成一行（靠编辑器软折行；表格、列表、代码块除外）——diff 干净、评审省力。
- **中英混排**：中文与英文、数字、行内代码之间加一个半角空格；中文用全角标点（，。；：！？（））。
- **禁 emoji**；直给结论。功能性符号只放行 `→`。
- **只写当前状态**：历史、过程、被否方案不进正文——分别去 git、笔记、`rejected/`。
- **明文：不设任何字数、篇幅、时效预算。** 没有最少行数、没有上限、没有复核周期；长度凭「写够合约、删掉推理记录与装饰」判断。机器不数行数，也不查 `Updated:` 的新鲜度。
- 一概念一词；新术语先在正文定义再用。

### 链接与检索

引用一律相对 Markdown 链接，目标必须存在（可机械校验）；正文不写裸路径。外部 URL 只作定位符：不保证可达、检查跳过、不触发抓取。

禁全局 `INDEX.md`——目录即索引；检索用全文检索工具（下文配方以 `rg` 为例，无 `rg` 用等价工具按同参数替代）：

```bash
# 1. 全工作区检索（排除两个归档区）
rg --hidden -g '!.agents/archive/**' -g '!.agents/notes/archived/**' <关键词> .agents/ docs/

# 2. 只搜决策笔记（含 rejected，排除 archived）
rg --hidden -g '!.agents/notes/archived/**' <关键词> .agents/notes/

# 3. 按类型列文档（模式锚定文件头，避免命中正文骨架示例）
rg -U -l '\A#[^\n]*\n\nType: plan$' .agents/plans/

# 4. 按状态列文档（同样锚定文件头）
rg -U -l '\A#[^\n]*\n\nType: [a-z]+\nStatus: superseded$' .agents/

# 5. 找入链（归档前必跑：还有谁指向这篇）
rg -n '\]\([^)]*<目标文件名>' .agents/ docs/
```

批量语料目录（外部文档镜像、采集数据）：`rg` 检索补一条 `-g '!<语料目录>/**'`；检查脚本用 `--exclude <语料目录>`（绝对路径的 exclude 按字面比较、经符号链接别名时不生效，见「配套脚本规格」的说明），或在目录内放空标记文件 `.agents-raw` 整目录豁免（见「配套脚本规格」的豁免清单）。

### 配套脚本规格

**位置与锚点。** 配套机器件只有一支脚本 `check-docs.mjs`：只用 Node 内置模块（Node ≥ 18），无依赖、不联网、不执行文档内代码。工作区根取**调用时的工作目录**，该目录须自身含 `.agents/` 目录——默认调用下不满足即退出码 2，不自脚本位置、也不向父目录上溯（上溯会命中 `~/.agents` 一类无关祖先）。脚本文件位置不限（可搬出 `.agents/tools/`），但一律以调用目录为基准，故调用前先 `cd` 到工作区根。结构判定以根下的 `.agents/` 目录为锚（不以路径段）。每次调用先打印被检树，再列告警。

**调用与退出码。**

```bash
node .agents/tools/check-docs.mjs [路径…]            # 报告模式：列发现，不失败
node .agents/tools/check-docs.mjs --strict [路径…]   # 严格模式：任一发现即失败
```

| 退出码 | 含义 |
|---|---|
| 0 | 检查完成且未发现问题；非严格模式跑完即 0（发现问题在输出里逐条列出） |
| 1 | `--strict` 且发现至少一个问题 |
| 2 | 无法完成检查——扫描面为空、路径不存在、根锚点缺失（默认调用下）、内部错误；两种模式都不得返回 0 |

退出码 0 在非严格模式下有歧义——它同时表示「无发现」与「有发现、已列出」。**任何读退出码的门禁必须带 `--strict`**；报告模式是给人看的巡检面，不是判据面。

扫描面：未给路径参数时取默认两根 `.agents/` 与 `docs/`（`.agents/` 是根锚点，缺失即退出码 2；`docs/` 存在才扫），默认两根与 `--exclude` 的相对值以工作区根（即调用目录）为基准；给出路径参数时以给出的路径为完整扫描面（不叠加默认），显式路径按调用目录解析——调用前先 `cd` 到工作区根，或传绝对路径；`--exclude <路径或 glob>` 从扫描面减去（归一后为空的值报用法错误，不静默空转）；绝对路径的 exclude 按字面比较，经符号链接别名（如 macOS 的 `/tmp` 与 `/private/tmp`）时不生效——传 realpath 后的路径，或改用相对路径。显式路径的扫描面内没有 `.agents/` 子树时，结构组不执行：注记走 stderr，且汇总行自带「结构组未执行」标注（只跑编码预检与链接组）。结构锚存在但 `.agents/` 下五个家（`plans/`、`research/`、`notes/`、`skills/`、`archive/`）一个都没有时同样注记「结构组无判定对象」——空 `.agents/` 会与完整树同形全绿，是已知的假绿形态。**扫描面只收 `.md`（大小写不敏感）**——`.mdx`、`.markdown` 不进面，宿主文档用这些扩展名时「全绿」不覆盖它们。非 git 环境同面工作（纯文件系统遍历）；符号链接按真实路径解析去重，不跟随指向扫描面外的链接。输出先给被检树（调用目录绝对路径 + 面描述），再逐条给「组号 + 文件：行号 + 判据」。

**编码预检 + 3 组检查（报告组号 0 至 3）。**

| # | 组 | 判据（命中即报） |
|---|---|---|
| 0 | 编码（预检） | 文件含无法按 UTF-8 解码的字节或 NUL 字节（检出 U+FFFD 替换字符或 NUL）——报，并注明其余判据不可信。 |
| 1 | 头块与生命周期 | 类型化文档（定义见「3 行头块」）必须有 `Type:`、`Status:`、`Updated:` 三行且顺序固定；Type 不在 9 类内、Status 不在该类型允许集内、`Updated:` 非 `yyyy-mm-dd`、字段值残留 `<占位符>`——报。`Status: superseded` 无 `Superseded-by:`——报；`Superseded-by:` 的裸路径形态（非 Markdown 链接）目标不存在——报（Markdown 链接形态的目标存在性归组 3）。活动笔记（`notes/` 下非 `archived/`）：标题后的第一个非空行必须是 `Status:`，取值与所在 lifecycle 目录一致；`rejected` 的 `—` 后原因为空——报；`notes/` 下不在 lifecycle 目录（proposed / implemented / rejected）的笔记——报。两个归档区（`.agents/archive/**` 与 `.agents/notes/archived/**`）中带类型头块的文档必须有 `Archived: yyyy-mm-dd` 行；目录入口页（`README.md`）与说明性文件不适用。 |
| 2 | 家与命名 | `.agents/` 下类型与家不符——报；**带类型头块的文档住在 `.agents/` 之外**（如 `docs/`，九类的家都在 `.agents/` 下）——报，扫描面内无结构锚时不判（避免误伤外部路径巡检）；日期型文档文件名不以 `yyyy-mm-dd-` 开头——报（只查 plans/research 家与 notes 活动区）；目录名不合 kebab-case（小写字母、数字、连字符）——报（只查 `.agents/` 子树）。 |
| 3 | 链接 | 相对 Markdown 链接目标不存在——报（只查行内 `[x](y)` 形态；引用式与脚注定义不查）；锚点、协议相对 `//` 与带 scheme 的外部 URL 跳过；扫描含归档区。 |

**不查清单（明示）。** 围栏代码块语言标注、标题层级跳级、表格竖线数、行尾空白、文件末尾换行、段落连排、中英空格、半角标点、emoji——九项机器不查、不进 `--strict`，责任归写作纪律与评审（细则见「写作规则」）：修法没有歧义、收益低，不值得占提交路径。

**类型枚举的两份。** 类型有两份表示：本规范的 9 类文档表（人读权威）与脚本内联的「类型 → 家 → 允许状态」表（机器读，约 20 行）；改类型表必须两份同批改——一致性靠人工纪律，无机内自检。

**豁免清单。**

- 目录级（任何组都不进）：`.git/`、`node_modules/`；`--exclude` 给出的路径；含空标记文件 `.agents-raw` 的目录（批量原始语料整目录豁免，仍应有一篇 survey 或 reference 说明它是什么、怎么采的）。
- 组级：组 0 编码预检对全部扫描文件生效；归档区只受归档头（组 1 的一部分）与链接（组 3）管辖（理由见「归档」）；组 1 只读头块（首个标题后连续的 `键: 值` 行块）；围栏与行内代码中的同形文本不参与任何组判定；但头块字段值按字面读、不剥行内代码——字段值不要包反引号（`` Updated: `2026-10-20` `` 会被报「非 yyyy-mm-dd」）；HTML 注释段本身不参与组 3 判定（注释段之外的可见文本照常判定；整行都在注释内的行整行豁免）。

**诚实条款。**

- **空集不冒充通过**：扫描面为 0 个文件时输出「未检查任何文件」并以退出码 2 结束——没检查不等于检查通过。
- **锚点断言只锚根**：默认调用下根锚点缺失必红（退出码 2）；显式路径的面内无 `.agents/` 子树时，结构组不执行——注记走 stderr，汇总行自带「结构组未执行」标注。部分改名仍可能以退出码 0 加注记告终：不静默，但也不是失败。
- **只证明机械子集**：脚本通过不证明文档合规——节的完整性、事实真假、因果质量、时效新鲜度都不在机器判定面。
- **非 git 环境降级**：脚本不读 git；「永不删除」「`Updated:` 诚实性」「并行会话纪律」在无 git 时没有佐证，只剩纪律（见「适用边界」）。
- **异常必须响**：脚本内部错误、无输出、被中断——非零退出，不静默返回 0。

**钩子归采用方。** 规范不分发钩子、不自动安装任何东西；要挂提交拦截，采用方自己装一支 `.git/hooks/pre-commit`（git 静默忽略没有执行位的钩子，`chmod +x` 不能漏）：

```bash
printf '#!/bin/sh\nnode .agents/tools/check-docs.mjs --strict\n' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

装完验证：提交一份坏文档应被拦下。

注意：检查脚本读工作树、不读索引。不带路径的 `git commit` 提交的是索引版本——先 `git add` 坏版、改好工作树再提交，提交进去的仍是未经检查的版本，改完务必重新 `git add`；带路径的 `git commit -- <路径>` 提交的是工作树版本，与检查面一致。另：工作树里的未跟踪半成品也在扫描面内，会拦停与它无关的提交。

### 存量树只读纳管

存量项目采用本规范时：

1. 先登记纳入管理的根（默认 `.agents/` 与 `docs/`，或项目自己的既有目录），登记写在项目 `README.md` 或 `AGENTS.md` 里——纯文本，不建注册表文件。
2. 存量文档的原生生命周期、编号、命名保持原样；本规范的头块与 Status 只对纳入后新写、新改的文档生效。
3. 规则不回溯：不为合规批量补头块、改格式、修链接；不把「存量清理」设为采用前提。
4. 受机器消费的文件（被脚本、构建或注册表按路径引用的清单与生成物）不移动、不改名；要引用它们用链接，不动本体。
5. 检查脚本的默认面是 `.agents/` 与 `docs/`；登记的其他根不会自动进扫描面——在调用里显式传路径、用报告模式（不带 `--strict`）巡检。提交闸门只挂默认面——存量根传进 `--strict` 会被存量告警一直拦下（存量清理不设期限）；闸门启用前先把默认面内的既有告警修清或排除。纳入根内的存量文件不被特殊对待——要免检按目录写 `--exclude`，或用 `.agents-raw` 标记整目录豁免。「规则不回溯」指不为合规批量追改，不是机器不报。
6. 存量文档在下次被实质修改时自然补齐头块与格式——更替靠修订，不靠运动。

### 归档

- **何时归档**：过时优先状态翻转；只有冷历史（不再维护、不再被引用）才归档。**永不删除。**
- **归档四步**（第 3、4 步缺一步都会留下断链或静默错链，真实事故形态；类型化文档第 2 步缺行由组 1 报出）：

1. **移动**：类型化文档移入 `.agents/archive/`（可加品类子目录）；笔记移入 `.agents/notes/archived/`（扁平放置）。
2. **加行**：头块末尾加 `Archived: yyyy-mm-dd`；原有 `Type:`、`Status:` 保留，作为它退役前的身份。
3. **重写自身相对链接**：逐条按目标归档后的位置重核——加品类子目录时深了一层，上行链接各补一层 `../`，同级链接对未同批归档的目标失效；平铺时深度不变，上行链接大体照旧，须改的是同级链接与指向同批归档件的链接。漏改时目标若仍存在会静默改指：加子目录时 `../README.md` 从 `archive/plans/` 解析到 `archive/README.md`，平铺时同级 `README.md` 从 `archive/` 解析到同一处。
4. **修入链**：全仓扫描指向旧路径的相对链接，同批改到新位置（配方见「链接与检索」第 5 条）。

**检查面。** 归档区不是豁免区——归档头（组 1）与链接（组 3）覆盖归档区，这正是四步第 3、4 步与类型化文档第 2 步的机器验证面。

**冻结。** 归档件永久不改；机器不做哈希封印，冻结靠纪律与评审——改动不会被机器发现（明示取舍，见「适用边界」）。

## 适用边界

- **机器只证明机械子集**：格式与链接可查；节的完整性、事实真假、结论质量、时效不查——检查全绿不等于文档合规。
- **明示取舍**：自检只留少数硬断言（空集必红、根锚点缺失必红（默认调用下）、异常非零），覆盖弱于逐规则负例夹具；风格面不设机器判据（见「不查清单」），漂移只剩写作纪律与评审；哈希封印不做，归档冻结与「永不删除」只剩纪律与评审，机器不能证明它们被遵守；复核周期与 `Updated:` 新鲜度检查不做，日期诚实性靠写作者。
- **类型表是上界不是配额**：9 类基于单仓实测的用量分布；短文档为主的项目可以删减类型与建议节——规范只约束保留项的行为。
- **解耦判据只核验机械子集**：链接零命中与零依赖可跑；「不含宿主云环境、数据库、CI、域名或业务脚本名」靠评审，不做词表扫描——词表会变成又一套门禁。
- **归采用方**：钩子、CI、编辑器集成、评审流程、权限模型；存量迁移与批量修复不承诺（见「存量树只读纳管」）。
- **证据边界**：全部拦截数据来自单仓 12 天拦截台账的实测（2026-10-05 至 10-16、615 行）；其他仓的破坏面分布未知，格式规则的漏网率在无门禁条件下无法外推。
- 脚本面向 Node 运行环境；没有 Node 的项目可以只采用文本约定部分，检查脚本不构成采用前提。
